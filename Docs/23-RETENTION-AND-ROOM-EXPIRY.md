# Хранение данных и завершение срока жизни комнат

Этапы B/C требования FR-19. Цель — действующая очистка по понятным правилам, без удаления материалов, которые ещё нужны другой учётной записи, комнате или выполняемой выгрузке. Периоды ниже — настройки продукта, не заключение о законодательстве страны размещения.

## Правила продукта

| Данные | Когда становятся доступны для очистки |
|---|---|
| Удалённый пакет или оформление | Через 30 дней после удаления; при удалении аккаунта — через 30 дней после удаления аккаунта |
| Готовая или неудачная загрузка | Через 30 дней после последнего изменения статуса; временный входной файл должен быть убран |
| Незавершённая загрузка | Истекает через 24 часа по существующему правилу |
| Журнал действий действующего аккаунта | Через 90 дней |
| Журнал удалённого аккаунта | Через 30 дней после удаления аккаунта |
| Истёкшие/отозванные учётные данные | Через 30 дней после прекращения действия, когда на них больше не ссылаются загрузки |
| Тексты жалоб/решений удалённого пользователя | Через 30 дней после удаления аккаунта; статус и время решения сохраняются, авторский текст заменяется отметкой об удалении |
| Лобби без действий | Через 7 дней после последнего принятого действия участника |
| Незавершённая игра без действий | Через 30 дней после последнего принятого действия участника |
| Завершённая игра | Через 30 дней после завершения |
| Любая комната | Не позднее 90 дней после создания при исправной работе очистки |

У комнаты применяется ближайший из её сроков. Переподключения, чтение табло, heartbeat и автоматические таймеры не продлевают хранение. Принятые действия и присоединение участников продлевают срок неактивности, но не предел 90 дней.

Это сроки допуска к очистке: фоновый процесс проверяет данные раз в минуту ограниченными порциями. При недоступности БД/хранилища удаление повторяется. Точные секунды физического удаления и облачные резервные копии не обещаются.

## Зависимости и приватность

- Материал с закреплённой версией в живой комнате сохраняется до удаления последней такой привязки. Очистка комнаты удаляет её сессии, приглашение, журнал, результаты, места участников и привязки пакета/темы.
- Одинаковый файл может использоваться несколькими материалами и владельцами. Байты удаляются только после исчезновения последней ссылки; удаление одной учётной записи не удаляет чужую копию.
- Действующая аренда экспорта защищает собственные материалы, ссылки загрузок и записи аккаунта до окончания подготовки. Собственные жалобы и решения по чужим материалам читаются из согласованного снимка PostgreSQL: удалённые до начала снимка записи могут отсутствовать, уже прочитанный снимок сохраняется до конца транзакции. Чужие файлы в экспорт не входят. После подготовки ZIP независим от исходных файлов.
- Готовые загрузки не являются бессрочным хранилищем. Прикреплённые файлы остаются в версиях материалов; отдельный неприкреплённый результат после срока очищается.
- Имя и учётные данные удалённого пользователя недоступны сразу по существующему правилу. Минимальный технический ID может остаться для связей с чужими решениями модерации; оригинальные имя, пароль и тексты не сохраняются в такой записи. Гостевые игроки не определяются по совпадению имени аккаунта.
- Очистка материала удаляет его историю модерации и жалоб вместе с ним. Для живых чужих материалов статус/время действий удалённого автора остаются, тексты его действий помечаются удалёнными.

## Технический контракт

Фоновая очистка транзакционно записывает ключи кандидатов на удаление объектов **до** удаления метаданных. Кандидаты сохраняются при сбоях и обрабатываются повторно. Перед каждым удалением под общим advisory lock проверяются все владельцы: оригиналы/варианты пакетов и тем, активные и готовые загрузки. Тот же lock уже защищает резервирование объектов при импорте. Общее правило ссылок выносится в `internal/blobrefs`, без двух расходящихся SQL-копий.

Очистка метаданных блокирует аккаунт, проверяет аренду экспорта и актуальные зависимости. Порядок блокировок: общий GC guard → аккаунт → очищаемая сущность. Нет сетевого удаления файлов под блокировкой аккаунта. Порции ограничены; отдельное удаление объекта имеет короткий timeout. Ошибки хранятся безопасным кодом, а не текстом с адресами/секретами провайдера.

Для комнат добавляются `last_activity_at` и `finished_at`, существующие записи получают консервативные даты миграции. Удаление проверяет текущий срок повторно под блокировкой комнаты и fencing игрового движка. Кешированный обработчик комнаты прекращает принимать команды, останавливает таймеры, освобождает соединения и удаляется из кешей. Параллельный join/command не оживляет удалённую комнату; неопределённый результат COMMIT сверяется с БД либо закрывается безопасно.

Подключённые клиенты получают терминальный `room_expired`; очередь старых кадров отбрасывается, автоматическое переподключение и повтор команд прекращаются. Старое приглашение показывает понятное сообщение о недоступной комнате. Участникам доступны срок и ссылка на правила хранения; API срока — только с действующим токеном участника.

Экспортные временные файлы размещаются в отдельном приватном каталоге внутри DATA_DIR. После получения исключительного владения движком запуск удаляет только файлы экспорта этого каталога, оставшиеся от предыдущего процесса. Посторонние файлы и общая системная временная папка не очищаются.

## Границы

Физическое удаление распространяется на известные зарегистрированные объекты. Очиститель не перечисляет весь бакет: произвольные посторонние объекты не удаляются. Резервные копии и повторное применение удалений после восстановления требуют отдельной эксплуатационной процедуры; этот этап не выдаёт непроверенную облачную политику за реализованную.

## Безопасное удаление из хранилища

Для S3 сервер требует включённое версионирование и проверяет его при запуске. Каждая успешная запись должна возвращать ненулевой неизменяемый VersionId; при выключении версионирования новая загрузка не объявляется успешной. Очистка перечисляет до 100 версий только известного ключа за проход и удаляет конкретные VersionId, включая маркеры удаления. Запрос без VersionId никогда не отправляется. Старый запрос, завершившийся после тайм-аута, поэтому не уничтожает новую версию. Нулевые/отсутствующие VersionId не удаляются автоматически; старое неверсионированное содержимое требует отдельного переноса в подходящее хранилище.

После получения списка версий повторно проверяется живая транзакция с GC guard: потеря соединения БД во время перечисления запрещает отправку удаления. Локальное хранилище дополнительно сериализует публикацию и удаление файлов блокировкой каталога ОС между процессами; короткая проверка guard выполняется под этой блокировкой. Целевая серверная ОС — Linux, файловая система должна поддерживать flock; на неподдерживаемых платформах запись не заменяет это гарантией только внутри процесса.

У S3-ключа сервиса нужны GetBucketVersioning, ListBucketVersions, DeleteObjectVersion и обычные права чтения/записи. Хранилище без версионирования нельзя считать взаимозаменяемым в этом режиме. Повторные записи одного хеша могут создавать дополнительные физические версии: расходы хранилища следует измерять отдельно от логической квоты аккаунта. Незарегистрированные ключи и версия с внешними ограничениями retention/object-lock не обходятся.

Основание: [AWS DeleteObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_DeleteObject.html), [AWS ListObjectVersions](https://docs.aws.amazon.com/AmazonS3/latest/API/API_ListObjectVersions.html), [Yandex DeleteObject](https://yandex.cloud/ru/docs/storage/s3/api-ref/object/delete). Реальная облачная конфигурация ещё не проверена.

## Приёмка

PG/объекты: границы 30/90 дней, активный экспорт, закреплённые версии, чужие общие байты, готовые загрузки/receipts, повтор после сбоя Delete/COMMIT, отмена/ограниченный объём работы, удаление секретов и редактирование своих текстов без изменения чужих. Миграции вверх/вниз.

Комнаты: сроки лобби/игры/завершения/90 дней; действия продлевают только неактивность; автоматические события не продлевают; гонки retirement/join/command/загрузка actor, fencing, освобождение pins и лимита 1000 комнат, терминальный WebSocket и отсутствие повторов. Полный Go race и браузерная проверка с искусственно состаренными собственными тестовыми комнатами.

Статус: реализовано и проверено локально 21.10.2026. Полный Go race с PostgreSQL/медиа, vet/build, 98 тестов веба, check без ошибок/предупреждений и сборка прошли. Chromium: срок/терминальное закрытие комнаты без переподключения, выгрузка ZIP, полный проход на 12 игроков. Независимый обзор нашёл гонку неопределённого удалённого DELETE; воспроизведена падающим тестом и исправлена удалением конкретных версий. Дополнительные проверки принудительно обрывают PostgreSQL во время получения версии и проверяют блокировку локальной публикации; проходят. Реальная S3-инфраструктура и длительная нагрузка ещё не проверялись.

Отложенная мелочь обзора: текст публичной политики должен уточнить, что ранее начатый срок удаления материала продолжает действовать после удаления аккаунта. Исправление включено в финальную редактуру до публичного выпуска; фактическая очистка использует более раннее из двух оснований. Резервные копии/восстановление и юридическая проверка остаются отдельными задачами эксплуатации.
