# SIBrowser: полный импорт и ежедневное обновление

`sibrowser-sync` обходит HTML-выдачу SIBrowser, скачивает SIQ и отправляет их штатному ingest. Готовые, играбельные пакеты автоматически публикуются. Авторы и ссылка на исходную карточку сохраняются; неизвестная лицензия остаётся неизвестной. Скачивание оригинала из нашего публичного каталога выключено, игра доступна.

## Подготовка

1. Применить миграции, запустить API и обработчик медиа. Новый CLI включён в Docker image; локальная сборка: `go build -o bin/sibrowser-sync ./cmd/sibrowser-sync`.
2. Создать отдельный аккаунт и назначить ему admin через `go run ./cmd/admin role USERNAME admin`. Выпустить API-токен с `drafts:read` и `drafts:write`. Получить **ID аккаунта**, а не username, в ответе `/api/account/me`.
3. Настроить источник и квоты в той же БД, что использует API. Значения ниже — пример для сервера с достаточным диском: 100000 пакетов и 1 TiB логического хранения. Реальный размер полного архива неизвестен; квота учитывает оригиналы, ревизии и производные медиа. У обычных пользователей остаются 200 пакетов и 10 GiB.

```sh
# DATABASE_URL уже установлен в окружении.
go run ./cmd/sibrowser-sync --configure-owner=ACCOUNT_ID \
  --pack-limit=100000 --storage-limit-bytes=1099511627776
```

Владелец источника закрепляется навсегда. Повтор команды с тем же ID меняет квоты. Другой ID отклоняется: смена учётной записи не должна создавать дубликаты старых пакетов. Источник работает только с активным admin; удаление аккаунта или потеря роли останавливают синхронизацию.

## Локальный запуск

Передать `DATABASE_URL`, `SI_API_URL` (origin API) и `SI_API_TOKEN` через защищённое окружение. Токен не передавать аргументом команды. API по умолчанию требует HTTPS, кроме loopback. `--allow-http-api` предназначен для доверенной внутренней Docker-сети. HTTP-редиректы API запрещены. Токены проекта действуют 30 дней: обновляйте токен в окружении cron до истечения срока; владелец источника при ротации остаётся тем же.

```sh
# Первый импорт, без фиксированного ограничения числа страниц/пакетов.
go run ./cmd/sibrowser-sync --mode=full --timeout=168h > full-report.json

# Последующие обновления.
go run ./cmd/sibrowser-sync --mode=incremental > daily-report.json

# Пробный ограниченный запуск: создаёт и публикует настоящие пакеты.
go run ./cmd/sibrowser-sync --mode=full --max-pages=1 --max-items=2
```

Без `--mode` используется `incremental`. Пока первый полный обход не закончен, этот режим также выполняет полный обход с checkpoint. `--max-pages` ограничивает продвижение по страницам; до двух повторно проверяемых страниц перед checkpoint не расходуют этот лимит. Финальная сверка начала выдачи тоже имеет сохраняемый checkpoint. По достижении `--max-pages`, `--max-items` или deadline запуск считается неполным. По умолчанию deadline — 23 часа, интервал запросов к источнику — 1 секунда. `--interval=2s` снижает нагрузку. Архивы обрабатываются последовательно; один архив ограничен 250 MiB, HTML страницы — 4 MiB.

## Docker и cron

В `.env` задать `SI_SYNC_API_TOKEN`; остальные параметры основной платформы остаются прежними. После обновления образа выполнить штатные миграции и перезапустить API.

```sh
docker compose --profile sync build sibrowser-sync
docker compose --profile sync run --rm sibrowser-sync \
  --configure-owner=ACCOUNT_ID --pack-limit=100000 \
  --storage-limit-bytes=1099511627776

docker compose --profile sync run --rm sibrowser-sync \
  --mode=full --allow-http-api --timeout=168h
```

Пример cron ежедневно в 04:15 по часовому поясу машины, с абсолютным путём к checkout. Каталог логов создать заранее, настроить ротацию и контроль exit code средствами эксплуатации.

```cron
15 4 * * * cd /srv/si-platform && docker compose --profile sync run --rm --no-deps sibrowser-sync --mode=incremental --allow-http-api >> /var/log/si-platform/sibrowser.jsonl 2>> /var/log/si-platform/sibrowser.err
```

Использовать `--no-deps` в cron только при уже работающем API/БД. Планировщик автоматически не устанавливается. Одновременный запуск full/incremental отклоняется PostgreSQL lock; нельзя запустить второй импорт после потери соединения lock без завершения работы первого процесса. Потеря соединения отменяет его запросы; запись прогресса защищена поколением запуска.

## Повторы и восстановление

- Прерывание: повторить команду. ID, входные параметры и checkpoint находятся в PostgreSQL; потеря scratch-volume не теряет прогресс.
- Неопределённый результат API: повтор используется с тем же ID и SHA; успешная загрузка/публикация не повторяется физически.
- Сетевые ошибки, 429, 5xx: до трёх непосредственных попыток обращения к источнику, затем отложенная попытка минимум через час с учётом Retry-After. После исправления проблемы можно повторить команду позже.
- Истёкшая или потерянная staged-загрузка: повторно скачивается и проверяется SHA, загрузка восстанавливается под прежним receipt автоматически. Конфликт offset/срока загрузки не означает удаление пакета.
- `rejected`: архив повреждён, превышает лимит, вместо него вернулся HTML, либо пакет не прошёл обработку/проверку игры. После исправления причины запустить с `--retry-rejected`. Неуспешная загрузка возобновляется под прежним receipt/upload ID; готовый пакет заново не создаётся. Если ошибочный пакет уже импортирован как черновик, требуется исправление оператором; автоматический перезапуск не переписывает его ревизии.
- `source_content_changed`: источник заменил файл после фиксации SHA. Автоматической замены опубликованной версии нет; требуется разбор оператором.
- Исчерпание квоты: увеличить квоту служебного владельца и проверить свободное место. Ошибка `processing_draft_quota` требует `--retry-rejected` после исправления.
- `suppressed`: пакет удалён, снят с публикации или изменён оператором. Автоматический retry не восстанавливает его. Блокировка источника/отзыв токена также не обходятся.

История исходных ID сохраняется независимо от запусков. Полный повтор обходит страницы, но не скачивает опубликованные пакеты заново. Daily просматривает выдачу до трёх подряд страниц, полностью известных на момент последнего завершённого обхода (находки прерванного запуска эту границу не сдвигают); новый пакет после первой знакомой карточки не теряется. Полный обход заканчивается дополнительной проверкой начала выдачи. Статусы ошибок сохраняются независимо от продвижения по страницам.

Быстрый daily предполагает, что новые публикации добавляются в начало выдачи по дате. Для поздних вставок в старую часть выдачи рекомендуется периодический `full`, например раз в неделю. Изменение уже опубликованных файлов и автоматическое удаление вслед за источником не входят в синхронизацию.

## Отчёт

stdout содержит JSON: `run_id`, `mode`, `pages`, `discovered`, `published`, `skipped`, `errors`, `complete`, `next_page`. `published` включает восстановление подтверждения уже выполненной публикации; `skipped` — знакомые карточки (один ID может встретиться на нескольких страницах). Ошибки содержат внешний ID, состояние и безопасный код; токены и подписанные download URL не логируются.

Коды завершения: 0 — текущий обход завершён без новых ошибок; 1 — ошибка/неполный обход; 2 — неправильная конфигурация; 3 — другой запуск держит lock. Старые rejected не делают каждый следующий запуск неуспешным. Сводка сохранённых проблем:

```sql
SELECT state, count(*) FROM source_items WHERE source='sibrowser' GROUP BY state;
SELECT external_id, state, error, attempts, next_attempt
FROM source_items WHERE source='sibrowser' AND state IN ('retryable','rejected','suppressed')
ORDER BY updated_at DESC LIMIT 100;
```

## Зависимость от внешнего источника

На 23 октября 2026 `robots.txt` SIBrowser содержит `Disallow: */direct_download`. Ссылка скачивания перенаправляет на VK; ограниченный пробный запрос вернул ZIP, но доступность всех файлов не проверена. Эксплуатация должна учитывать правила и доступность источника. CLI не обходит авторизацию/капчу: HTML вместо архива считается ошибкой. Разрешены HTTPS origin SIBrowser и домены VK/userapi; DNS и каждый редирект проверяются, приватные адреса запрещены. Токен платформы используется только отдельным API-клиентом.

Полный обход означает обход доступной выдачи и учёт результата каждой записи, а не обещание импортировать повреждённые, удалённые, слишком большие или неподдерживаемые файлы. Проверки разработки используют синтетические SIQ, локальный HTTP и изолированные схемы PostgreSQL; рабочий каталог автоматически не заполняется.

## Полные карточки и обложки

`--mode=metadata` обновляет **только уже опубликованные импортированные пакеты**: описания, всех авторов, теги, даты, имена/размеры исходных файлов, проценты типов вопросов и категорий, счётчик скачиваний источника, ссылки на исходные сообщения, структуру и текст предпросмотра. Он не загружает SIQ, не создаёт пакеты и не меняет checkpoint полного обхода. По умолчанию снимок и изображение обновляются не чаще раза в сутки, ошибки — через час. `--force-metadata` обновляет независимо от срока; `--max-items=N` ограничивает число карточек за запуск. Новые импорты и встретившиеся в обычном обходе карточки обновляются автоматически, неуспешные задачи повторяются отдельно от ошибок SIQ.

```sh
# Догрузить существующий каталог, не возобновляя full:
sibrowser-sync --mode=metadata --timeout=24h
# Проверить ограниченную выборку повторно:
sibrowser-sync --mode=metadata --force-metadata --max-items=10
```

Полный metadata-проход необходимо запускать отдельно (например, ежедневно после incremental), чтобы обновлялись и старые карточки вне первых страниц. Поле `metadata_errors` отчёта не переводит импорт SIQ в rejected; в metadata-режиме ошибки дают ненулевой код завершения. Счётчики `metadata_updated` и `covers_updated` отделены от публикаций. `covers_updated` включает подтверждение отсутствия внешней обложки.

Обложки скачиваются с маршрута собственного пакета `/packages/ID/logo.webp` (до 5 MiB), проходят штатную изолированную обработку изображения (до 16 млн пикселей), сохраняются в object storage и выдаются нашим API только для опубликованного пакета. При отсутствии внешней обложки используется подготовленный логотип SIQ или текстовая заглушка. При прикреплении резерв ready-upload атомарно переходит в объём подготовленных вариантов обложки; повтор не списывает квоту заново. Исходное изображение остаётся временным объектом стандартного ingest до штатной очистки. Смена обложки отправляет прежние ключи в безопасный GC; удаление пакета удаляет снимок по FK. API экспорта аккаунта включает снимок и подготовленные изображения.

Метаданные и предпросмотр ограничены 512 KiB на карточку, HTML — 4 MiB. Разметка источника не исполняется; рекомендации и дубликаты мобильных блоков исключаются. Текст вопросов не входит в поиск; ответы и комментарии ведущего не выдаются публичным API карточки. Поиск и фильтр тегов учитывают новые сведения источника. Статистика и дата SIBrowser подписаны отдельно от сведений SIQ и статистики нашей платформы.

Для локального Docker Desktop вложенному bubblewrap могут требоваться `--security-opt seccomp=unconfined --security-opt systempaths=unconfined`; процесс API остаётся непривилегированным, медиапроцессор использует отдельные namespaces, точечные mounts и лимиты ресурсов. Это параметры локального запуска, не безусловное ослабление настроек compose для всех окружений. Image добавляет стандартный путь к приватной библиотеке PulseAudio, необходимой проверке ELF-зависимостей FFmpeg.


## Скачивания, оценки и лайки

Публичные карточки возвращают `engagement`: показатели источника отдельно от локальных и вычисленные итоги. `source_metadata.snapshot` хранит nullable `downloads`, `rating`, `rating_count`, `likes`; повторное сохранение снимка заменяет исходные значения и не затрагивает локальные голоса/скачивания.

Оценки 1–5 и независимые лайки доступны активным пользовательским сессиям через `GET/PUT /api/catalogue/{id}/vote`, тело PUT: `{ "rating": 5, "liked": true }`. `rating: null` снимает оценку, `liked: false` снимает лайк. Повторный PUT не создаёт новые голоса. Публичный API не раскрывает авторов оценок.

Средняя оценка объединяется с источником по числу голосов; без исходного количества отображается отдельно. Непредоставленные показатели остаются null. Скачивания считаются после успешной полной выдачи публичного SIQ и flush; HEAD, Range, ошибки и экспорт черновиков исключены. Это число полных передач, не уникальных пользователей.

На проверенных страницах SIBrowser есть скачивания, но рейтинг/лайки пока не подтверждены. Поддержка явной microdata `AggregateRating` (шкала 1–5) и `LikeAction` покрыта синтетическими тестами; реальные значения не подставляются из предположений. Синк автоматически не запускается.
