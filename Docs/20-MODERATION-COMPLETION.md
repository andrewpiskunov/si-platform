# Модерация: причины решений, жалобы и проверка медиа

## Результат

Автор видит причины возврата или блокировки своего пакета. Модератор просматривает текст, ответы и подготовленные медиа конкретной версии, рассматривает жалобы даже после новой публикации или снятия пакета. Продолжение FR-06/16; автоматическая модерация и юридическое подтверждение прав не добавляются.

## Решения

Используем существующие решения публикации и добавляем поля единственного окончательного решения жалобы. Отдельная система тикетов избыточна; повторное использование блокировки для любого закрытия жалобы не позволяет отклонять необоснованные обращения. История решений доступна автору и действующему модератору, без данных заявителя.

- GET `/api/drafts/{id}/decisions?after_id=0&limit=50`: `{items,next_after_id?}`, ID по возрастанию. Элемент: `id,revision,decision,reason,created_at`. Автор или действующий модератор, existing drafts:read for author API token; чужой автор доступа не получает. Заблокированный пакет доступен для диагностики, существующая политика удалённых пакетов/авторов сохраняется.
- GET `/api/reports?status=open&after=<id>&limit=50`: `{items,next_after?}`, status=open|resolved, limit1..50, cursor32hex, стабильный ID по возрастанию. Только действующая сессия модератора/администратора; API tokens запрещены.
- POST `/api/reports/{id}/resolution`: `{disposition:"dismissed"|"resolved",reason}`. Непустая UTF-8 причина, до2000символов/8000байт, без управляющих символов кроме перевода строки/табуляции. Одинаковый повтор возвращает принятое решение; другое содержимое после закрытия —409. Это не блокирует пакет. Работает после смены версии, снятия, удаления пакета/автора; полномочия исполнителя проверяются в транзакции.
- Поля жалобы: `resolution` (open empty; decision/resolved/dismissed/legacy), `resolution_reason`, `resolved_by` (ID или null), `resolved_at` (ISO timestamp или null). Старые закрытые записи получают legacy с неизвестными исполнителем/временем; данные не выдумываются. Новые закрытия атомарно фиксируют исполнителя/время; закрытые записи больше не меняются.
- `block` допустим для любой существующей версии активного пакета и блокирует весь пакет, закрывая все открытые жалобы с решением decision. `approve/reject` сохраняют требование текущей pending-версии и закрывают только её открытые жалобы. Ранее закрытые жалобы не перезаписываются. Удалённый пакет не требуется блокировать: жалоба закрывается явно.

## Интерфейс

В редакторе — отдельная история решений с причинами и загрузкой следующих50. На модерации — очередь, фильтр открытых/рассмотренных жалоб, пагинация, раздельные формы причин и явные действия «Отклонить жалобу», «Завершить рассмотрение», «Заблокировать пакет». Ошибка сохраняет список и введённую причину, обновление можно повторить.

Просмотр закреплён за pack/revision, один выбранный вопрос одновременно. Используется существующий QuestionPreview: текст, правильные ответы, пояснения, медиа по нажатию, обычное/экономное качество. Смена версии/вопроса уничтожает старый медиакомпонент. Файлы доступны только через существующий авторизованный endpoint; заблокированные файлы остаются запрещены. Запоздавший ответ не заменяет более новый выбранный просмотр.

## Проверка

Реальный PostgreSQL: миграция legacy/down/up; автор/чужой/модератор/отозванная сессия/смена роли; повтор и конкурентные закрытия; жалоба старой версии после публикации, снятия и удаления; блокировка старой версии закрывает все открытые и сохраняет старые решения. HTTP проверяет строгий JSON, курсоры и scope. Chromium проверяет путь автора/модератора, причины, обе категории жалоб, медиа закреплённой версии, сетевую ошибку и мобильную страницу. Публичные DTO не раскрывают личность заявителя.

## Статус

Реализовано. Полный Go race с PostgreSQL/медиа, vet/build, 88 веб-тестов и проверка типов/сборка прошли. Chromium проверил закреплённые медиа без автозапуска, причину возврата у автора, отклонение/закрытие жалоб, блокировку старой версии, восстановление после ошибки и мобильные размеры. Все 11 браузерных сценариев прошли, включая запоздавший просмотр и пагинацию. Независимый обзор разрешил объединение без критических и существенных замечаний. Небольшая правка текста ошибки при конкурентном решении жалобы оставлена на финальную вычитку; первое решение и введённая причина сохраняются.
