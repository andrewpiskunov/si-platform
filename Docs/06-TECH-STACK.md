# Конкретный стек: Go, база и хранение файлов

**Дата:** 20.10.2026. **Go подтверждён пользователем.** Библиотеки ниже выбраны по документации для первого прототипа; совместная работа и нагрузка ещё не проверены. Провайдер файлов выбран условно: регион и бюджет не подтверждены. Фронтенд рассматривается [отдельно](07-FRONTEND-CHOICE.md).

## 1. Предлагаемый состав

| Задача | Компонент | Зачем он нужен |
|---|---|---|
| HTTP API | Go `net/http` + `github.com/go-chi/chi/v5` | Маршрутизация, группы, middleware на стандартных обработчиках |
| Игровые соединения | `github.com/coder/websocket` | WSS, чтение/запись сообщений, context, ping/pong |
| Хранение данных | PostgreSQL + `github.com/jackc/pgx/v5`, `pgxpool` | Транзакции, пул соединений, запросы к PostgreSQL |
| Запросы | `sqlc` | Генерация типизированного Go-кода из нашего SQL |
| Миграции | `github.com/pressly/goose/v3` | Версионируемые изменения схемы |
| Фоновые задания | `github.com/riverqueue/river` | Очередь в PostgreSQL, отдельные worker-процессы |
| MCP | `github.com/modelcontextprotocol/go-sdk` | Официальный SDK, транспорт Streamable HTTP |
| Файлы | `github.com/aws/aws-sdk-go-v2/service/s3` | S3-клиент, потоковая и составная загрузка |
| Облачное хранение | Yandex Object Storage + Cloud CDN, условно для РФ/СНГ | Оригиналы, производные медиа и оформление; отдельная доставка файлов |

Используем поддерживаемые стабильные версии. Точные версии Go, PostgreSQL, модулей и образов фиксируются перед прототипом после проверки совместимости и уязвимостей; номера веток `/v5` и `/v3` не заменяют фиксацию релиза. Сейчас зависимости не установлены и облачные ресурсы не созданы.

## 2. Почему эти библиотеки

### HTTP: chi поверх стандартной библиотеки

| Вариант | Сильная сторона | Цена для проекта |
|---|---|---|
| Только `net/http` / ServeMux | Минимум зависимостей, стандартные интерфейсы | Организацию групп маршрутов и цепочек middleware оформляем самостоятельно |
| **chi** | Совместимость с `http.Handler`, композиция маршрутов и middleware | Валидацию входа, ошибки и контракты API всё равно проектируем сами |
| Gin | Готовая модель контекста, binding и middleware | Обработчики теснее зависят от API фреймворка |

Выбираю **chi**: игровому сервису полезна небольшая HTTP-обвязка вокруг самостоятельной логики комнат. Роутер не должен определять модель игры. Все три варианта пригодны; основание выбора — интерфейсы и объём необходимой обвязки, не обещание максимальных RPS. Источники: [net/http](https://pkg.go.dev/net/http), [chi](https://github.com/go-chi/chi), [Gin](https://github.com/gin-gonic/gin).

### WebSocket: coder/websocket

У библиотеки есть API с context, ping/pong и закрытием соединений. Альтернатива — [Gorilla WebSocket](https://github.com/gorilla/websocket): её можно выбрать при потребности в конкретных настройках буферов или при наличии опыта команды. Оснований объявлять Gorilla непригодной нет. Выбор coder — удобство интерфейса для нашего жизненного цикла соединений. [Документация coder/websocket](https://github.com/coder/websocket).

В приложении отдельно реализуем Origin allowlist, авторизацию каждой команды, лимит чтения 16 KiB и очередь записи до 64 KiB. На соединение — управляемое чтение и последовательная отправка; на комнату — один владелец состояния. Компрессия сообщений первоначально выключена; её пользу измеряем. Общий таймаут короткого HTTP-запроса не должен обрывать долгую WebSocket-сессию.

Библиотека не решает восстановление игры, порядок нажатий и защиту от повторов. Это контракт [игрового движка](03-ARCHITECTURE.md).

### PostgreSQL: pgx + sqlc

`pgx` предоставляет PostgreSQL-драйвер и пул; `sqlc` генерирует интерфейсы по SQL. Такой набор позволяет явно проверять запросы, индексы и транзакцию «решение + ID команды + номер события». [pgx](https://github.com/jackc/pgx), [sqlc](https://sqlc.dev/).

Альтернатива — ORM, например [GORM](https://gorm.io/docs/): удобен для типовых операций и связей. Он не считается автоматически медленным, но в нашем критическом пути явный SQL проще сопоставить с требованиями долговечности. Миграции ведём через [goose](https://github.com/pressly/goose), запускаем отдельным шагом развёртывания, не конкурентно каждым игровым узлом.

### Задания и MCP

[River](https://riverqueue.com/docs/transactional-enqueueing) позволяет записать изменение данных и задание в одной транзакции PostgreSQL. Это подходит импорту, обработке изображений тем и генерации вопросов. Задание может выполняться повторно: нужны идемпотентность, учёт внешних вызовов и ограничение попыток. Пулы и квоты worker-процессов отделяем от игровых; при конкуренции за БД сначала ограничиваем фоновые работы. Redis/Kafka для первоначальной очереди не требуются.

Для внешних ИИ-клиентов используем [официальный MCP Go SDK](https://github.com/modelcontextprotocol/go-sdk). Права пользователя, лимиты, проверка версии черновика и запрет самостоятельной публикации остаются нашей прикладной логикой.

## 3. Выбор объектного хранилища

**Рабочее решение: Yandex Object Storage + Cloud CDN при размещении для аудитории РФ/СНГ.** Русский язык запроса не подтверждает географию пользователей; это допущение для проекта, подлежащее пересмотру в D-09. Преимущество для старта — возможность собрать вычисления, PostgreSQL, файлы и доставку в одном облаке. Превосходство по цене или задержке пока не доказано.

| Вариант | Когда выбирать | Что проверять |
|---|---|---|
| **Yandex Object Storage + Cloud CDN** | Базовый кандидат для размещения в РФ/СНГ | Приватная доставка, доступность из сетей аудитории, счёт за хранение/запросы/трафик/CDN |
| Selectel S3 | Альтернатива при размещении основных серверов у Selectel | Нужные методы S3, схема CDN и доступа, итоговая стоимость |
| AWS S3 + CloudFront | Кандидат для международного размещения и команды с опытом AWS | Регион, условия аккаунта/оплаты, стоимость межрегионального и исходящего трафика |
| Cloudflare R2 | Кандидат при большой доле исходящего трафика | Ограничения S3 API, приватная выдача через Workers, доступность для аудитории |
| Собственное S3-совместимое хранилище | Когда есть эксплуатационная команда и измеренная экономия | Диски, отказоустойчивость, резервные копии, обновления и круглосуточная поддержка |

У R2 нет платы за исходящий трафик самого хранилища, но остаются хранение, операции и возможные расходы Workers. Это не означает бесплатную доставку всего сервиса. Совместимость S3 также не означает идентичность всех возможностей. Источники: [Yandex S3 API](https://yandex.cloud/en/docs/storage/s3/), [Yandex pricing](https://yandex.cloud/en/docs/storage/pricing), [Selectel](https://docs.selectel.ru/s3/), [AWS pricing](https://aws.amazon.com/s3/pricing/), [R2 pricing](https://developers.cloudflare.com/r2/pricing/), [R2 compatibility](https://developers.cloudflare.com/r2/api/s3/api/).

Код использует AWS SDK for Go v2 с настраиваемыми endpoint/region и небольшим интерфейсом хранения. Доставка через CDN — отдельный адаптер: S3-совместимость не переносит правила авторизации CDN автоматически. [AWS SDK](https://docs.aws.amazon.com/sdk-for-go/v2/developer-guide/go_s3_code_examples.html).

## 4. Как хранить и выдавать файлы

Оригиналы, карантин и готовые файлы разделены по правам и срокам жизни. Метаданные, владелец и разрешения находятся в PostgreSQL; байты — в объектном хранилище. Загрузка в карантин не означает разрешения на игровую выдачу. Нужны удаление незавершённых multipart-загрузок, lifecycle временных файлов, версии и проверяемая резервная копия оригиналов.

Для Yandex предлагается такая схема: публичные обложки и готовые общедоступные темы идут через публичный CDN; приватные игровые файлы — через отдельный CDN-ресурс с подписанными ссылками. API проверяет роль и фазу игры перед выдачей ссылки. Срок ссылки — до 60 секунд, клиент при необходимости получает новую. Подпись проверяется и при попадании в кеш. [Yandex secure tokens](https://yandex.cloud/en/docs/cdn/concepts/secure-tokens).

**Origin тоже должен быть закрыт от обхода.** Для первого прототипа предлагаем отдельный Go media-origin: CDN обращается к нему по защищённому соединению с проверяемым секретом ресурса, а он потоково читает приватный S3. Он не хранит игровые комнаты и не буферизует целый видеофайл. Наличие и корректность передачи секрета, поддержка Range и стоимость дополнительного перехода проверяются до принятия схемы. Одна только фильтрация по общим IP CDN не доказывает доступ именно нашего ресурса.

Если этот вариант не проходит проверку, D-09 пересматривается до запуска: потребуется другой способ защищённого origin или другой CDN. Публичный bucket для приватных вопросов не является запасным вариантом.

Отзыв доступа сразу запрещает получение новых ссылок. Уже выданная ссылка может работать до истечения 60 секунд; начатая перед истечением загрузка может завершиться позже. Очистка кеша не заменяет авторизацию. Для немедленного отзыва каждого запроса потребуется дополнительная проверка актуальных прав на выдаче; такой режим отдельно оценивается по стоимости. Уже скачанные данные отозвать нельзя.

## 5. Что подтвердить перед основной разработкой

| Проверка | Результат |
|---|---|
| Интеграция Go | Вход → WSS → команда → транзакция → событие → переподключение; повтор команды не начисляет очки снова |
| Совместимость библиотек | Фиксированные версии, лицензии, проверка уязвимостей, корректное завершение и обновление процессов |
| Очередь заданий | Отмена, повтор, падение worker, транзакционная постановка; фоновые задания не срывают цели игры |
| S3 + CDN | Multipart/abort, CORS, Range, кеш, подписи, закрытый origin, удаление, восстановление оригинала; проверка обхода прямым URL |
| Нагрузка | Стенд NFR-01, полные комнаты с 12 игроками, p95/p99, RSS, GC, медленные клиенты и потеря узла |
| География и стоимость | Пробы из реальных сетей аудитории; расчёт при 100/1 000/10 000 соединениях по фактическим размерам файлов |

Сравниваем полную стоимость: хранение оригиналов и производных + версии/копии + запросы + доставка + CDN + media-origin + сопровождение. Результат — зафиксированные D-04/D-09 с измерениями, а не объявление любого облака «самым быстрым».
