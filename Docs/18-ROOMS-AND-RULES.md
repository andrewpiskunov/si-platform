# Комнаты, доступ и общие правила

Дополнение к FR-02/09/13. Этап закрывает публичные комнаты, внешнюю голосовую ссылку и отображение правил. Лимиты остаются: ведущий, до 12 игроков и 20 зрителей. Удаление участников и отзыв их доступа — следующий отдельный этап.

## Поведение

| Возможность | Договорённость |
|---|---|
| Приватность | При создании по умолчанию «По приглашению». «Публичная» явно разрешает любому посетителю войти в свободную роль. Старые комнаты остаются приватными. |
| Изменение | Текущий ведущий меняет доступ и голосовую ссылку в лобби или на паузе. Переданный гостю статус ведущего даёт те же права. Команда требует актуальный номер состояния и защищена от повторов. |
| Приглашения | Переход из публичной в приватную комнату атомарно отключает все прежние приглашения. Ведущий создаёт новую ссылку отдельной кнопкой. Уже вошедшие остаются. Обновление ссылки в публичной комнате не закрывает свободный вход. |
| Список игр | Отдельная страница показывает только публичные незавершённые комнаты: название, состояние, занятые места и доступные роли. Считаются места, а не подключения. Заявка на вход заново проверяет приватность, фазу и лимиты на сервере. |
| Голос | Необязательная HTTPS-ссылка с показом адреса назначения, открываемая отдельно. Сайт не загружает её содержимое и не встраивает сторонний голосовой сервис. Ссылку видят только вошедшие участники. |
| Правила | Все роли видят текущие таймеры, режим кнопки, окно случайного выбора, фальстарт, штрафы и допуск в финал. Версия правил указана явно. Правила уже начатого вопроса зафиксированы. |
| Изменение правил | Новая версия вызывает доступное уведомление; первый вход задаёт исходную версию. Переподключение к той же версии не повторяет уведомление, пропущенная новая версия сообщает об изменении. Несохранённые правки ведущего не стираются приходящим снимком. Изменение попадает в журнал. |

Публичность комнаты открывает участие в игре, но не выдаёт доступ к черновику, исходному SIQ или экспорту чужого пакета. Название публичной комнаты открыто всем; приватные вопросы, имена участников, голосовая ссылка и токены в список не попадают.

## Контракт

- `RoomSettings {visibility: "private"|"public", voice_url: string}` в `State`, `View`, запросе создания (`settings` необязателен). Отсутствующая настройка старой комнаты означает private/пустую ссылку. `set_room_settings` v2: полный payload `{settings: RoomSettings}`, обязательные `command_id` и `expected_seq`; host-only, lobby/paused, незавершённая игра. Visibility обязательна; voice_url можно опустить (пустая ссылка). Unknown fields, явные null-строки и неверные значения отвергаются.
- Голосовая ссылка: пустая или не более 2048 UTF-8 байт, абсолютный HTTPS URL с host; без userinfo, пробелов, обратной косой черты и управляющих символов. Никакого server-side fetch. В браузере `target="_blank" rel="noopener noreferrer"`, понятная подпись hostname.
- `GET /api/rooms?after=<room_id>&limit=<1..50>`: по умолчанию 50, после ID в лексикографическом порядке. `{items:[{room_id,title,phase,players,spectators,player_limit:12,spectator_limit:20,can_join_player,can_join_spectator}],next_after?:string}`. Только закреплённые комнаты из room_packs, public, phase != finished. `Cache-Control: no-store`. Некорректный cursor/limit → 400. Список не создаёт room actors.
- Join без invite разрешён только текущей публичной комнате. Для приватной требуется действующее 64-символьное приглашение. Проверка идёт под блокировкой строки комнаты вместе с добавлением участника; старый список не даёт обхода. Игроки входят только между вопросами, зрители — до завершения, с прежними лимитами.
- Migration11: производная STORED `rooms.visibility` из snapshot.settings.visibility с default private для отсутствующего поля; check значений, частичный индекс публичных незавершённых комнат. Любое сохранение snapshot обновляет индекс автоматически. sqlc пересоздаётся обычным инструментом.
- При public→private в той же транзакции команда заменяет invite_hash случайным невосстановимым значением; секрет нигде не возвращается/не журналируется. Повтор команды не отключает более позднее новое приглашение. Кнопка обновления ссылки использует существующий отдельный endpoint. UI явно очищает прежнюю ссылку при наблюдаемом переходе и предупреждает о необходимости новой.
- `PublicEvent.rules_change?:{version:number,rules:Rules}` только при увеличении версии; результаты продолжают проецировать исключительно явные публичные поля, без raw payload.
- `game.CanJoinRole(state, role)` — общее правило допуска для списка и AddParticipant. ProjectAt/legacy возвращают нормализованные settings. `settings` не передаёт URL до аутентификации.

## Приёмка

Проверяются приватный default/миграция, запрет чужих настроек/пропущенного seq/неверных URL, paused/transfer/replay, отсутствие секретов в списке и журнале, публичный вход без аккаунта, границы 12/20, пагинация и завершение, атомарное закрытие входа и отзыв старого приглашения без потери текущих сессий. Chromium: host/player/spectator, правила и уведомления/reconnect/несохранённая форма, голосовая ссылка без сетевой загрузки, создание/список/вход/смена приватности/новое приглашение, клавиатура и ширины 390/820/1440. Полный локальный race/type/build/browser набор и один независимый обзор.

Это локальная функциональная приёмка; тысячи пользователей, другие браузеры и промышленная эксплуатация проверяются отдельным этапом.

## Статус

Реализовано. Полный Go race с PostgreSQL/медиа, vet/build, 70 веб-тестов, type-check/build и восемь Chromium-сценариев прошли. Приёмка нашла потерю слишком раннего ввода до гидратации; форма теперь блокируется до подключения обработчиков, регрессия проверена. Дополнительно проверено длинное непрерывное название комнаты: оно переносится на узком экране; меню модератора проверено после гидратации. Независимый обзор этапа ещё не завершён.
