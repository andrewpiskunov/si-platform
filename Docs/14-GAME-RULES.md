# Игровые правила: контракт второго поколения

Основа — FR-02/08–13/17 и матрица P0 в [требованиях](02-REQUIREMENTS.md). Этот этап завершает текстовые игровые механики; подготовка медиа, собственные темы, ИИ/MCP и эксплуатация продолжаются отдельно. Не меняем правила уже созданных комнат: старые снимки без `gameplay` остаются на движке v1; новые комнаты получают v2.

## Поведение

| Режим | Порядок и начисление |
|---|---|
| Обычный | Ведущий показывает вопрос и открывает кнопку. Ошибка: штраф, если включён; этот игрок больше не отвечает на вопрос, остальные продолжают. Верный ответ: начисление и право выбора следующего вопроса. |
| Ставка | Открытый аукцион по очереди, затем отвечает один победитель; выигрыш/штраф равны ставке. Выбравший вопрос участвует даже при малом счёте; остальные — при счёте выше номинала. Шаг — степень 10, не превышающая минимальную положительную цену раунда. После первого выбирающего остальные идут по возрастанию счёта, равные — по месту; очередь циклическая. После ва-банка доступны только пас/ва-банк. |
| Общая ставка | Допущенные игроки со счётом >0 одновременно делают скрытую ставку 1…счёт; после вопроса отвечают независимо. Ставка фиксируется один раз, чужие ставки до раскрытия не видны. |
| Секрет | Выбравший вопрос назначает получателя до показа темы/цены. `selectionMode=any/exceptCurrent` определяет возможность оставить себе. Получатель выбирает цену из диапазона, если параметр задан, и отвечает один. |
| Всем | Все игроки, включённые в состав вопроса, отвечают отдельно; ведущий оценивает каждого. |
| Без риска | Отвечает выбравший вопрос. По умолчанию верный ответ даёт 2× стоимость, неверный — 0. |
| Финал | Участники со счётом >0 удаляют темы до одной, по возрастанию счёта; при равенстве — порядок мест. Последовательность циклическая, начало сдвинуто так, чтобы последняя удаляемая тема досталась лидеру. Играется первый вопрос оставшейся темы: скрытая ставка, закрытые ответы, поочерёдное раскрытие и оценка. |

Поведение аукциона, типов и параметров сверяется с первичным кодом SI, зафиксированным на commit `7f8cda975fdd71aef69fa4eef0572d41417d8900`: [ScriptsLibrary](https://github.com/VladimirKhil/SI/blob/7f8cda975fdd71aef69fa4eef0572d41417d8900/src/Common/SIPackages/ScriptsLibrary.cs), [GameController](https://github.com/VladimirKhil/SI/blob/7f8cda975fdd71aef69fa4eef0572d41417d8900/src/SICore/SICore/Clients/Game/GameController.cs), [RulesSettings](https://github.com/VladimirKhil/SI/blob/7f8cda975fdd71aef69fa4eef0572d41417d8900/src/SICore/SI.Contracts/RulesSettings.cs), [Question](https://github.com/VladimirKhil/SI/blob/7f8cda975fdd71aef69fa4eef0572d41417d8900/src/Common/SIPackages/Question.cs). Порядок мест при равенстве, допуск только положительного счёта для общей ставки и действия таймаутов ниже — явно выбранные правила нашей платформы.

## Настройки и время

Пресет «Классика»: выбор 30 с, обычный ответ после кнопки 10 с, спецвопрос 30 с, ставка 30 с, финал 60 с; каждое значение 5–120 с. Штрафы включены, кнопка по первому принятому сервером нажатию; фальстарт включён с блокировкой 3 с. Пресет «Друзья»: те же сроки, штрафы и фальстарты выключены. В ручном режиме окно случайного выбора 100–300 мс, блокировка фальстарта 1–5 с. Числа на клиенте не определяют время события.

У каждого этапа есть уникальный ID и серверный срок. Раннее нажатие во время показа вопроса сохраняет блокировку; это подтверждённое изменение состояния. В случайном режиме повтор одного игрока не увеличивает его шансы; кандидаты и случайное зерно сохраняются до выбора победителя. Утрата ведущего и перезапуск приостанавливают все активные этапы. На паузе остаток времени заморожен; после перезапуска просроченный этап остаётся на паузе и получает нулевой остаток, без скрытого начисления очков.

Таймаут аукциона означает пас; отсутствующая общая ставка исключает игрока из данного вопроса. Истечение времени ответа закрывает сбор и передаёт решение ведущему; сервер не определяет правильность. Истечение времени выбора/получателя/цены помечает этап просроченным, ведущий может выполнить действие за игрока. После истечения открытой кнопки ведущий раскрывает ответ или явно продлевает этап. Таймер оценки ведущего не начисляет очков автоматически.

Правила меняются в лобби или между вопросами и получают новую версию. У вопроса фиксируется собственная копия правил. `answerDuration` — секунды пакета; задаёт ожидание кнопки и прямой/общий ответ, но не обычный ответ после нажатия. Значение вне 5–120 с диагностируется до игры; не обрезается молча. Длительность отдельных фрагментов текста/медиа — другой параметр.

## Секретность и управление

Сервер строит представления заново по роли. Игрок видит собственные ставку/ответ и факт готовности остальных. Ведущий получает тексты ответов после закрытия сбора; ставки закрыты и от ведущего до раскрытия. Правильный ответ доступен ведущему после показа вопроса, остальным — после команды раскрытия/завершения обычного вопроса. Завершение всей игры само по себе не раскрывает скрытые ответы и невыбранные вопросы.

Ведущий может передать роль подключённому зрителю на паузе; бывший ведущий становится зрителем. Роль проверяется по сохранённому состоянию, а не по кешу сокета. Запрос апелляции относится к конкретному решению. Исправление решения создаёт компенсирующее начисление с причиной; после начала зависимого вопроса требуется отдельное изменение счёта с причиной, принятое до следующего этапа ставок. Во время принятых ставок изменение счёта запрещено до явного перезапуска этапа. Перезапуск очищает только решения текущего незавершённого этапа и меняет его ID, чтобы старые команды не сработали.

Состав отвечающих фиксируется в начале вопроса, включая временно отключившихся. Их восстановление не теряет ставки/ответы; таймауты позволяют закончить этап без них. Новый игрок входит только между вопросами. Зритель не становится участником вопроса из-за смены вкладки. Приглашение можно перевыпустить; старое перестаёт принимать новых участников, существующие сохраняют доступ.

## Проверка

Обязательны: все перечисленные типы; неверный ответ с продолжением; фальстарт с сохранением блокировки; одновременные ставки/ответы без конфликта общей версии; случайное окно с единственным сохранённым победителем; перезапуск/пауза на каждом этапе; скрытые данные в ответах, событиях и переподключении; передача ведущего с отключением бывшего; корректировка без повторного начисления; финал от исключения тем до итогов. Обычный и финальный сценарии проверяются в браузере.

## Уточнения совместимости

- Числовая ставка допускает максимум игрока даже вне сетки шага. Принятая ставка исключает соперников со счётом ≤ неё. Ва-банк — отдельный режим действия, числовая ставка на весь счёт сама его не включает. При отсутствии первой ставки таймаут назначает номинал, дальше — пас.
- Native v5 secret без `price` сохраняет номинал и не предлагает выбор цены. Legacy cat/bagcat без cost после нормализации имеет `{minimum:0,maximum:0,step:0}`: это минимальная/максимальная цена раунда. `[100;500]` без шага — только концы; `[100;550]/200` разрешает 100,300,500,550. Native `step=0` разрешает любое целое внутри диапазона; malformed ranges отклоняются с диагностикой.
- Нулевая цена корректного обычного вопроса допустима в v2: начисление/штраф равны 0. Верхняя граница цены 100000; ставок/счёта — 1000000000, без переполнения. Legacy v1 продолжает требовать положительную цену.
