# Встроенный ИИ-помощник (FR-14/18)

## Результат для автора

В редакторе автор задаёт тему, аудиторию и сложность, выбирает одну тему или пакет по шаблону (до 100 вопросов). До запуска видит максимальный расход и остаток месячного лимита. Результат остаётся отдельным предложением: можно исправить вопросы, ответы и источники, отклонить или явно принять. Принятие добавляет тему в редактируемый пакет либо создаёт новый частный черновик; публикация остаётся обычным отдельным действием. Все сгенерированные факты и ссылки изначально неподтверждённые.

## Выбор подхода

1. Выбран: серверная очередь PostgreSQL и адаптер OpenAI Responses, ограниченный структурированный текст. Совместим с текущим Go-сервером, контролируемый расход и восстановление.
2. Прямой вызов из браузера: раскрывает ключ и позволяет обходить лимиты; отвергнут.
3. Свободный агент с поиском и инструментами: увеличивает цену и поверхность доступа; отложен. MCP — следующий самостоятельный этап на прикладных сервисах, а не условие внутреннего помощника.

## Провайдер и граница обещаний

Реальный режим включается только при явном AI_PROVIDER=openai, ключе, имени модели, тарифах входа/выхода и месячном лимите. AI_PROVIDER=fixture — отдельный локальный режим с детерминированными тестовыми вопросами и видимой маркировкой «тестовый провайдер; это не генерация моделью»; разрешён только при loopback LISTEN_ADDR, не использует ключ и не обращается в сеть. Без настройки UI показывает недоступность, ничего не имитирует. HTTP-адаптер использует Responses API, store:false, strict text.format JSON schema; обрабатывает отказ, incomplete, неверную структуру и usage. Никаких инструментов, загрузки ссылок, файлов или скрытых запросов по URL автора. Ключ остаётся на сервере, ошибки провайдера не попадают в браузер/БД/логи.

Цена — внутренняя оценка бюджета по настроенным тарифам, не платёж/счёт пользователю и не гарантия тарифа провайдера. Модель/тарифы задаёт оператор: не зашиваем выдуманные актуальные цены. Адаптер проверяется локальным HTTP-провайдером, браузер — явно обозначенным fixture-режимом; платных запросов в реализации/приёмке нет. store:false не является обещанием нулевого хранения самим провайдером.

## Запуск, лимиты и восстановление

- Запрос: mode=theme|pack, topic≤2000 символов, audience≤200, difficulty1..5, themes1..10, questions_per_theme1..10, всего≤100. Для theme themes=1. Только один обычный раунд, простые текстовые вопросы, цены100,200,…; медиа/финал добавляются в обычном редакторе.
- Сначала quote: сервер фиксирует нормализованный запрос, версию prompt/schema, модель/тарифы, max_output_tokens и input_tokens, полученные у провайдера для того же запроса. Данные уходят провайдеру уже при расчёте: UI говорит об этом до кнопки расчёта. Quote действует5мин, максимум1 текущая котировка на аккаунт; не чаще одного расчёта в10с на аккаунт и global2 semaphore, timeout15с, нет генерации.
- Деньги — целые microUSD, проверяемая арифметика без float/overflow; резерв округляется вверх по каждому виду токенов. max_output_tokens по умолчанию16384, оператор может установить256..64000; input≤32000. Оценка показывает возможность неполного результата при лимите.
- Start требует quote_id и idempotency_key; свежая авторизация до повтора. Под account row lock + коротким глобальным admission guard проверяются неистёкшая котировка, месячный UTC бюджет, ≤1 активное задание аккаунта, ≤20 queued+running глобально. Резерв/задание/receipt коммитятся атомарно до вызова generation. Повтор того же ключа возвращает то же задание; другой запрос с ключом —409. Квота не сбрасывается повторным входом.
- Два worker, каждый одно задание, provider timeout180с. Claim queued→running durable до исходящего запроса. Нет автоматического повторного generation после ошибки или перезапуска. Recover running→uncertain с сохранением максимального резерва, queued можно продолжить. Завершённые с известным usage расходуют рассчитанное фактическое значение; ошибочные ответы тоже могут стоить токенов. Недостоверный/превышающий лимит usage или неопределённый сетевой исход удерживает резерв; бюджет не уходит отрицательно и следующий платный запрос сам не запускается.
- Cancel queued отменяет и возвращает резерв. Cancel running отменяет локальный HTTP и помечает cancel_requested, но не обещает отмену у провайдера; известный usage учитывается, иначе uncertain. После подтверждённого завершения результат отменённого задания не применяется автоматически.
- Перед dispatch повторная проверка живого аккаунта и исходного credential/scopes. Отзыв до отправки отменяет queued без затрат. После отправки запрос нельзя надёжно отозвать у провайдера; сервер ограничивает время/расход, закрывает доступ удалённому аккаунту, не публикует результат.
- Очередь запускается только после exclusive engine ownership. Shutdown отменяет/дожидается workers; восстановление не повторяет running. Сетевых вызовов под DB/account lock нет.

## Результат и редактор

Строгий ответ: title, themes[{name,questions[{text,answer,sources:string[],comment}]}]. Проверить точное число, поля/длины, непустые ответы, дубликаты нормализованного текста; лишние поля/неверные размеры отклонить. Источник — строка, не доказательство; ссылки отображаются безопасно, никаких fetch/previews. Созданные IDs назначает сервер, не модель.

В UI редактируемый результат отделён от открытого документа до явного «Просмотрел; добавить». Для темы добавление в локальную рабочую копию использует существующий DraftEditor/CAS/autosave, не перезаписывает несохранённые изменения. Повторное добавление того же задания в одном редакторе предотвращается по job_id; автор может сознательно использовать результат в другом пакете. Для полного пакета новая приватная запись через существующий Create с ImportID=job_id даёт безопасный повтор после потери HTTP-ответа. Комментарий каждого вопроса сохраняет происхождение, дату и «факты/источники не проверены»; принятие означает решение автора использовать материал, а не автоматическую верификацию. Редактирование/проверка источников доступны обычными полями; источники/комментарии сохраняются в SIQ.

## Доступ, данные и API

GET /api/ai/status — authenticated usage/configuration, без ключей; POST /quotes; POST /jobs {quote_id,idempotency_key}; GET /jobs?after=…50; GET /jobs/{id}; POST /jobs/{id}/cancel. Сессия либо PAT ai:generate; чтение/отмена только свои, живой credential проверяется в транзакции. Применение нового пакета требует также drafts:write и явного reviewed=true; отдельный POST /jobs/{id}/draft с отредактированным ограниченным результатом, хеш первого применения, повтор того же результата идемпотентен, другого409. Нельзя передать model/baseURL/tariff из браузера. CSRF/origin/JSON/body caps как в текущих authoring endpoints.

История показывает состояния quoted/queued/running/ready/failed/cancelled/uncertain, максимум и факт расхода отдельно. Пустота/503/401 различаются; смена пользователя уничтожает прошлый результат, поздний запрос не возвращает его. Polling bounded, AbortController на уходе; reconnect не создаёт новую задачу.

AI metadata/request/result/cost входят в allowlisted account ZIP, без ключа/credential_id/raw response. Quotes после истечения чистятся, terminal jobs после90д (30д после удаления аккаунта); защищены owner export lease. Месячные агрегаты сохраняют расход независимо от удаления истории; прошлые месяцы можно удалить после90д, текущие нельзя. Неопределённый расход остаётся в агрегате месяца. AI blobs отсутствуют. Удаление аккаунта отменяет queued через worker, прекращает доступ немедленно.

## Приёмка

RealPG race: конкурентные reserve/duplicate/start/limit/cancel/revoke/month-boundary/restart; fakeprovider calls count exactly once; known usage and uncertainty settlement; no network under locks; schema/refusal/truncation/body-size/error redaction; account export and retention. Frontend tests stale-account/generation guards, editable review and no implicit publication. Browser with explicit local test provider: quote→start→review/edit→new private pack/theme→SIQ, cancel/failure, no duplicate request after retry; default disabled state. No claim of real model accuracy until separately authorized provider run and authored question review.

Технические источники: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [Responses и store:false](https://developers.openai.com/api/docs/guides/migrate-to-responses), [подсчёт входных токенов](https://developers.openai.com/api/docs/guides/token-counting). Это контракты API, а не подтверждение тарифа/качества выбранной модели.

Статус: спецификация следующего этапа; реализация и приёмка ещё выполняются.
