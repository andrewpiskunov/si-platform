# Браузерная игра и мастерская

Первый сквозной проход соединяет Go API, PostgreSQL, SvelteKit и приватное хранилище. Это рабочий этап полного MVP; остальные P0 перечислены в [статусе](11-IMPLEMENTATION-STATUS.md).

## Запуск

Нужны Go 1.27.3, PostgreSQL 18 и Node 26.10. Установите зависимости веба один раз: `cd web && npm ci`. Примените миграции `DATABASE_URL=… go run ./cmd/migrate`.

В одном терминале из корня:

```sh
DATABASE_URL='postgres://…' ALLOWED_ORIGIN='http://localhost:5173' go run ./cmd/server
```

В другом: `cd web && npm run dev`. Откройте **http://localhost:5173**. Vite передаёт HTTP и WebSocket в Go на 8080. `API_ORIGIN` — серверная настройка SvelteKit, не секрет в браузерной сборке. В production тот же origin обслуживается через reverse proxy. Compose содержит PostgreSQL, миграции, API, веб и Caddy; `docker compose up --build` открывает http://localhost:8080. Docker-конфигурация пока не запускалась в среде разработки без Docker.

`DATA_DIR` (по умолчанию `.local/data`) хранит оригиналы/файлы и временные загрузки. Для S3 задаются `S3_BUCKET`, `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, при необходимости `S3_PATH_STYLE=true`. Пустые ключи используют стандартную цепочку AWS credentials. Bucket создаётся оператором и остаётся приватным. S3 проверен через настоящий SDK с локальным HTTP-сервером; реальный облачный endpoint ещё не проверен.

## Пользовательский путь

1. Зарегистрируйтесь, откройте мастерскую. Создайте пакет или загрузите SIQ. Загрузка идёт частями до 4 MiB, продолжает с подтверждённого смещения; разбор выполняют два фоновых обработчика.
2. Редактируйте вопросы и ответы. Сохранение создаёт неизменяемую ревизию; при конфликте локальный текст сохраняется до вашего решения. Есть история, отмена, предпросмотр и экспорт SIQ.
3. Чтобы опубликовать, укажите автора, источник и основание использования; разрешение скачивать SIQ выбирается отдельно. Модератор проверяет конкретную ревизию. Её содержимое не меняется при дальнейшей работе автора.
4. Создайте комнату, выберите классическую, пиратскую или аниме-тему, пригласите игроков. Ведущий начинает раунд, выбирает вопрос из табло и открывает кнопку; первое принятое сервером нажатие даёт право ответить. Доступен также случайный выбор в коротком окне. Игрок/зритель входит без аккаунта.
5. После разрыва связи браузер восстанавливает участника по токену комнаты. Неопределённый результат команды повторяется с тем же ID; подтверждённые очки не начисляются дважды. Потеря ведущего приостанавливает текущий вопрос.

В мастерской также есть быстрый запуск собственного демонстрационного пакета. Он не требует копирования чужого каталога. Отдельная проверка 12 одновременных игроков: `go run ./cmd/demo` (создаёт временный аккаунт, выполняет игру, удаляет аккаунт).

## Модератор и права

Назначение роли выполняет оператор с доступом к БД, а не клиент сайта:

```sh
DATABASE_URL='postgres://…' go run ./cmd/admin role имя_пользователя moderator
```

Действие записывается в аудит. Модератор открывает `/moderation`, просматривает версию и принимает решение; жалоба всегда относится к конкретной версии. Блокировка запрещает новые игры и выдачу файлов. Снятие публикации скрывает карточку; уже начатая игра остаётся закреплена за версией. Удаление пакета или аккаунта владельца блокирует последующую выдачу и этой закреплённой версии.

Пароли хранятся как Argon2id, сессии/персональные токены — как хеши. Смена пароля отзывает все учётные сессии и API-токены. Публикация и управление аккаунтом недоступны через ограниченный токен MCP. Cookie HttpOnly/SameSite; Secure включается для HTTPS origin. Приглашение комнаты находится во fragment ссылки и не отправляется в Referer. Полный пакет не передаётся игрокам: табло содержит только названия, цены и отметки сыгранного.

## Границы этого этапа

- Новые комнаты используют правила v2: обычные текстовые вопросы, аукцион, секрет, общую ставку, вопрос всем, вопрос без риска и стандартный финал; фрагменты вопроса/ответа, таймеры, апелляции и передача ведущего описаны в [контракте](14-GAME-RULES.md). Старые комнаты сохраняют правила v1. Медиавоспроизведение — следующий этап. Формат SIQ распознаёт больше конструкций, чем текущий игровой адаптер; неподдержанная механика не подменяется обычным вопросом. Отдельный блок «Готовность к игре» показывает ограничения движка до создания комнаты; они не запрещают экспорт корректного SIQ.
- Импортированное аудио/видео получает `media_pending` до отдельной проверки кодеков. Медиа в редакторе выбирается из импортированного архива; отдельная загрузка медиа будет добавлена вместе с подготовкой файлов.
- Три готовые палитры охватывают оболочку страницы игровой комнаты; импорт своей темы, ИИ и MCP остаются в плане полного MVP.
- Экспорт аккаунта пока содержит данные профиля и метаданные токенов. Полный архив авторского содержимого, окончательная политика хранения/очистки и резервирование относятся к следующему этапу приватности/эксплуатации.
- Очистка неудачных импортов защищает общие хеши и готовые версии. Она не заменяет полную политику удаления опубликованных данных.

## Проверки

`TEST_DATABASE_URL=… go test -race ./...`, `go vet ./...`, `go build ./...`; в `web`: `npm run check`, `npm test`, `npm run build`. Тесты БД создают отдельные схемы. Проверяются конфликты ревизий, scopes, публикация/блокировка всех файлов, загрузки и восстановление worker после потери соединения, приватность табло, повтор выбора вопроса и независимость комнаты от новых правок автора.

Браузерная проверка: `cd e2e && npm ci && npx playwright install chromium && npm test` при запущенных API и вебе. Chromium также требует системные библиотеки Playwright; для другого адреса задайте `BASE_URL`. Скрипты создают временные аккаунты и удаляют их после проверки; снимки и SIQ сохраняются в `.local/browser`. Проверены 12 отдельных игровых контекстов, мобильная ширина 390 px, отсутствие ответа до раскрытия, восстановление счёта, экспорт/импорт, исправление неполного черновика, снятие публикации после редактирования и оформление всей страницы. Отдельный сценарий `rules.mjs` проверяет восстановление кнопки после фальстарта, неверный ответ с продолжением, закрытые ставки и ответы, удаление тем финала, раскрытие и оценку, передачу ведения с уходом прежнего ведущего и безопасный журнал. Все три сценария проходят без ошибок страницы. Это не заменяет проверку остальных браузеров и доступности.

При работе на Windows-диске из WSL файловый watcher Vite может не замечать правки. В таком окружении перезапустите dev-сервер перед проверкой изменений.

Нагрузочные бюджеты 10 000 подключений, 1 000 комнат и целевая память ещё не измерены. Успех теста на 12 игроков не является подтверждением этих бюджетов.
