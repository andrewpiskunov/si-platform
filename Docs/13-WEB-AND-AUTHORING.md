# Браузерная игра и мастерская

Первый сквозной проход соединяет Go API, PostgreSQL, SvelteKit и приватное хранилище. Это рабочий этап полного MVP; остальные P0 перечислены в [статусе](11-IMPLEMENTATION-STATUS.md).

## Запуск

Нужны Go 1.27.3, PostgreSQL 18 и Node 26.10. Для медиа также нужны Linux/WSL с доступными user namespaces, FFmpeg/ffprobe, bubblewrap и prlimit. Сервер проверяет настоящий запуск в sandbox при старте; пути переопределяются `MEDIA_FFMPEG`, `MEDIA_FFPROBE`, `MEDIA_SANDBOX`, `MEDIA_PRLIMIT`. Для явно выбранного текстового режима задайте `MEDIA_DISABLED=true`. Установите зависимости веба один раз: `cd web && npm ci`. Примените миграции `DATABASE_URL=… go run ./cmd/migrate`. Для поиска миграция 10 требует PostgreSQL 18 с UTF-8 и доступное расширение `pg_trgm`; миграционная роль устанавливает его в `public`. Перед обновлением остановите запись старой версии API, затем примените миграции и запустите новый API. Миграция 11 добавляет STORED-колонку публичности комнат и индекс: запланируйте окно обслуживания для переписывания таблицы; её размер и длительность на целевой БД ещё не измерены.

В одном терминале из корня:

```sh
DATABASE_URL='postgres://…' ALLOWED_ORIGIN='http://localhost:5173' go run ./cmd/server
```

В другом: `cd web && npm run dev`. Откройте **http://localhost:5173**. Vite передаёт HTTP и WebSocket в Go на 8080. `API_ORIGIN` — серверная настройка SvelteKit, не секрет в браузерной сборке. В production тот же origin обслуживается через reverse proxy. Compose содержит PostgreSQL, миграции, API, веб и Caddy; `docker compose up --build` открывает http://localhost:8080. Docker-конфигурация пока не запускалась в среде разработки без Docker.

`DATA_DIR` (по умолчанию `.local/data`) хранит оригиналы/файлы и временные загрузки. Для S3 задаются `S3_BUCKET`, `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, при необходимости `S3_PATH_STYLE=true`. Пустые ключи используют стандартную цепочку AWS credentials. Bucket создаётся оператором и остаётся приватным. S3 проверен через настоящий SDK с локальным HTTP-сервером; реальный облачный endpoint ещё не проверен.

## Пользовательский путь

1. Зарегистрируйтесь, откройте мастерскую. Создайте пакет или загрузите SIQ. Загрузка идёт частями до 4 MiB, продолжает с подтверждённого смещения; разбор выполняют два фоновых обработчика.
2. Редактируйте вопросы и ответы. Сохранение создаёт неизменяемую ревизию; при конфликте локальный текст сохраняется до вашего решения. Есть история, отмена, предпросмотр и экспорт SIQ.
3. Чтобы опубликовать, укажите автора, источник и основание использования; разрешение скачивать SIQ выбирается отдельно. Модератор проверяет конкретную ревизию. Её содержимое не меняется при дальнейшей работе автора.
4. Создайте комнату, выберите классическую, пиратскую или аниме-тему, пригласите игроков. Ведущий начинает раунд, выбирает вопрос из табло и открывает кнопку; первое принятое сервером нажатие даёт право ответить. Доступен также случайный выбор в коротком окне. Игрок/зритель входит без аккаунта.
5. После разрыва связи браузер восстанавливает участника по токену комнаты. Неопределённый результат команды повторяется с тем же ID; подтверждённые очки не начисляются дважды. Потеря ведущего приостанавливает текущий вопрос.

В мастерской также есть быстрый запуск собственного демонстрационного пакета. Он не требует копирования чужого каталога. Отдельная проверка 12 одновременных игроков: `go run ./cmd/demo` (создаёт временный аккаунт, выполняет игру, удаляет аккаунт).

## Модератор и права

Назначение роли выполняет оператор с доступом к БД, а не клиент сайта:

```sh
DATABASE_URL='postgres://…' go run ./cmd/admin role имя_пользователя moderator
```

Действие записывается в аудит. Модератор открывает `/moderation`, просматривает версию и принимает решение; жалоба всегда относится к конкретной версии. Блокировка запрещает новые игры и выдачу файлов. Снятие публикации скрывает карточку; уже начатая игра остаётся закреплена за версией. Удаление пакета или аккаунта владельца блокирует последующую выдачу и этой закреплённой версии.

Пароли хранятся как Argon2id, сессии/персональные токены — как хеши. Смена пароля отзывает все учётные сессии и API-токены. Публикация и управление аккаунтом недоступны через ограниченный токен MCP. Cookie HttpOnly/SameSite; Secure включается для HTTPS origin. Приглашение комнаты находится во fragment ссылки и не отправляется в Referer. Полный пакет не передаётся игрокам: табло содержит только названия, цены и отметки сыгранного.

## Границы этого этапа

- Новые комнаты используют правила v2: обычные текстовые вопросы, аукцион, секрет, общую ставку, вопрос всем, вопрос без риска и стандартный финал; фрагменты вопроса/ответа, таймеры, апелляции и передача ведущего описаны в [контракте](14-GAME-RULES.md). Старые комнаты сохраняют правила v1. Подготовка и совместный показ изображений, аудио и видео описаны в [медиаконтракте](15-MEDIA.md); сквозная браузерная приёмка пройдена. Формат SIQ распознаёт больше конструкций, чем текущий игровой адаптер; неподдержанная механика не подменяется обычным вопросом. Отдельный блок «Готовность к игре» показывает ограничения движка до создания комнаты; они не запрещают экспорт корректного SIQ.
- SIQ и отдельные файлы проходят одну изолированную подготовку; исходники сохраняются, для игры создаются обычная и экономная производные. Без обработчика импорт остаётся редактируемым с `media_pending`. Отдельная загрузка прикрепляется к текущей ревизии только после подготовки; загрузка из редактора и сохранение локальной правки проверены в Chromium.
- Три готовые палитры охватывают оболочку страницы игровой комнаты; импорт своей темы, ИИ и MCP остаются в плане полного MVP.
- Экспорт аккаунта пока содержит данные профиля и метаданные токенов. Полный архив авторского содержимого, окончательная политика хранения/очистки и резервирование относятся к следующему этапу приватности/эксплуатации.
- Очистка неудачных импортов защищает общие хеши и готовые версии. Она не заменяет полную политику удаления опубликованных данных.

## Проверки

`TEST_DATABASE_URL=… go test -race ./...`, `go vet ./...`, `go build ./...`; в `web`: `npm run check`, `npm test`, `npm run build`. Тесты БД создают отдельные схемы. `MEDIA_INTEGRATION=1` включает обязательный настоящий FFmpeg/sandbox в тестах; без этого флага проверки внешних инструментов явно пропускаются. В этой среде полный профиль инструментов загружается через `/home/andrew/.cache/si-platform-tools/media-env.sh`; это локальный путь, для другой машины используйте установленные бинарники и `MEDIA_*`. Проверяются конфликты ревизий, scopes, публикация/блокировка всех файлов, загрузки и восстановление worker после потери соединения, приватность табло, повтор выбора вопроса и независимость комнаты от новых правок автора.

Браузерная проверка: `cd e2e && npm ci && npx playwright install chromium && DATABASE_URL=… npm test` при запущенных API и вебе. `DATABASE_URL` здесь указывает на локальную БД этого API: сценарий каталога назначает модератором собственный временный аккаунт через операторский CLI. Это отдельный от `TEST_DATABASE_URL` стенд; публичную рабочую БД для браузерных тестов не используйте. Chromium также требует системные библиотеки Playwright; для другого адреса задайте `BASE_URL`. Скрипты создают временные аккаунты и удаляют их после проверки; снимки и SIQ сохраняются в `.local/browser`. Проверены 12 отдельных игровых контекстов, мобильная ширина 390 px, отсутствие ответа до раскрытия, восстановление счёта, экспорт/импорт, исправление неполного черновика, снятие публикации после редактирования и оформление всей страницы. Отдельный сценарий `rules.mjs` проверяет восстановление кнопки после фальстарта, неверный ответ с продолжением, закрытые ставки и ответы, удаление тем финала, раскрытие и оценку, передачу ведения с уходом прежнего ведущего и безопасный журнал. Сценарий `media.mjs` проверяет загрузку из редактора с несохранённой правкой, обычный/экономный предпросмотр, медленного участника, ошибку файла и повтор, скрытую вкладку, явное продление ожидания, общий показ PNG/аудио/видео, отсутствие повторной загрузки на старте, паузу, переподключение, приватность ответа и исходные байты в SIQ. Добавлен `themes.mjs`: пример ZIP, приватные версии, 12 участников, каталог в контексте комнаты, локальные настройки, смена на паузе и отзыв оформления; его контракт и проверки — в [Docs/16](16-CUSTOM-THEMES.md). Для media-сценария нужен `ffmpeg` в PATH либо `MEDIA_FFMPEG`; `npm run test:text` запускает только текстовые сценарии. `theme-regressions.mjs` проверяет повтор табло и читаемость светлых палитр; `authoring.mjs` — форму поиска/возраста, SSR и пагинацию, все перестановки, undo/сохранение выбора, SIQ и диагностические черновики. Его можно запустить отдельно через `DATABASE_URL=… npm run test:authoring`. Это не заменяет проверку остальных браузеров и доступности.

При работе на Windows-диске из WSL файловый watcher Vite может не замечать правки. В таком окружении перезапустите dev-сервер перед проверкой изменений.

Нагрузочные бюджеты 10 000 подключений, 1 000 комнат и целевая память ещё не измерены. Успех теста на 12 игроков не является подтверждением этих бюджетов.


Публичные комнаты доступны на `/rooms`. Приватность выбирается при создании; ведущий может изменить её и голосовую HTTPS-ссылку в лобби или на паузе. Перевод в приватную комнату отключает старые приглашения; новая ссылка выдаётся отдельной кнопкой. Места уже вошедших сохраняются. Все участники видят правила и уведомление о новой версии. Контракт — [Docs/18](18-ROOMS-AND-RULES.md).

`DATABASE_URL=… npm run test:rooms` из `e2e` проверяет создание, публичный вход игрока/зрителя без аккаунта, приватность/отзыв приглашений, внешнюю голосовую ссылку без автоматического запроса, несохранённые формы, реальное переподключение и пропущенную версию правил, пагинацию и ширины 390/820/1440 px. До подключения обработчиков форма создания недоступна для ввода, чтобы быстрые изменения не терялись при гидратации. Сценарий использует собственный временный аккаунт модератора через CLI и завершает свои публичные комнаты при очистке.
