# Лобби и начало игры

Цель: после создания комнаты понятно, какой пакет выбран, кто ведёт, кто играет и чего ждём перед стартом.

- Отдельный экран лобби в оформлении «Эфир»: пакет, ведущий с аватаром, 12 мест, готовность каждого, выбор первого раунда.
- Игрок самостоятельно включает и снимает готовность. Зритель и ведущий не отмечают готовность за игроков.
- Новые комнаты из веб-интерфейса ждут готовности всех игроков (минимум два). Ведущий может отключить это в настройках. Старые комнаты и API без нового параметра сохраняют прежнее поведение.
- Готовность хранится на сервере, видна всем и переживает переподключение. Это согласие начать, а не индикатор соединения или загрузки медиа.
- Вошедший новый игрок не готов. Удалённые участники не учитываются. Проверка действует только до первого раунда, затем остаётся обычное управление игрой.
- Приглашение остаётся в существующей панели комнаты; звук проверяется перед стартом. После старта показывается игровое табло, ведущий или выбирающий игрок открывает первый вопрос.

Протокол: `set_ready {ready: boolean}` только для активного игрока в lobby; сервер последовательно применяет команды без общего CAS (готовность разных игроков независима). Повтор команды обслуживает существующий журнал идемпотентности. `settings.require_ready` — необязательный boolean, отсутствие означает false. Нельзя прислать null. Начало раунда проверяется по актуальному состоянию сервера.

Не входит: загрузка пользовательских аватаров, встроенная голосовая связь, автоматический старт без ведущего.

Реализовано в основном приложении. Автоматические проверки:

- `go test ./...` с тестовым PostgreSQL: успешно, включая сервер и хранилище.
- 105 веб-тестов; Svelte/TypeScript: 0 ошибок и предупреждений; production-сборка успешна.
- Chromium: 12 участников, аватары всех игроков, блокировка старта, снятие/возврат готовности, сохранение после reload, первый вопрос, ответ, счёт и завершение. Ошибок страницы нет.
- Пользовательская тема: создание комнаты с отключённым ожиданием, 3 браузерных и 9 WebSocket-игроков, мобильный экран, смена темы и восстановление после перезагрузки — успешно.
- Независимый обзор: исправлен ложный конфликт после отключения ожидания; удалено повторное действие из проекции. Регрессии покрыты тестами.
