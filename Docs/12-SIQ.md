# SIQ: импорт, диагностика и экспорт

Реализован отдельный Go-модуль формата, общий для будущих редактора и игры. Он читает SIQ v4/v5, преобразует структуру во внутреннюю модель, выдаёт отчёт и экспортирует поддержанный документ в v5. Подключение к HTTP, хранению и игровому табло — следующие этапы.

## Проверка без сервера

```sh
go run ./cmd/siq sample /tmp/first-game.siq
go run ./cmd/siq validate /tmp/first-game.siq
go run ./cmd/siq convert /tmp/first-game.siq /tmp/converted.siq
```

`sample` создаёт собственный демонстрационный пакет из девяти вопросов; происхождение — в [examples](../examples/README.md). `validate` выводит JSON: название, число вопросов/файлов, `playable` и диагностику. При блокирующей проблеме код завершения ненулевой. `convert` не перезаписывает существующий файл; при ошибке удаляет частичный результат.

`playable` означает прохождение **структурного профиля**. Проверка кодеков, фактической длительности аудио/видео и подготовка медиаверсий будут выполняться отдельным этапом до допуска пакета к игре.

## Что сохраняется

- Раунды, темы, цены, метаданные, авторы, источники, правильные/неправильные ответы и комментарии ведущему.
- Последовательность question/answer, размещение контента, длительности до миллисекунд и ожидание завершения.
- Параметры v5, их вложенность и числовые множества; глобальные метаданные XML.
- Байты вложенных файлов; вычисляется SHA-256, проверяется ZIP CRC.

V4 `scenario` преобразуется с разделителем `marker`; `say` остаётся репликой ведущего, `voice` становится аудио. `auction` преобразуется в `stake`, `sponsored` — в `noRisk`, стандартные `cat/bagcat` — в `secret` с сохранением цены и выбора отвечающего. Специальные варианты вне P0 диагностируются. Распознавание типа в формате пока не означает реализацию соответствующего игрового правила.

Неизвестный тип/параметр/элемент/атрибут, произвольный script, HTML, внешнее или отсутствующее медиа блокируют структурную готовность и обычный экспорт. Отчёт содержит код и путь до проблемы; неизвестное не отбрасывается молча. Оригинал импортёр не изменяет; HTTP-слой будет хранить его отдельно от редактируемой модели. Внешние URL импортёр не загружает.

## Лимиты и защита

Оригинал ≤250 MiB, распаковка ≤1 GiB / 5 000 файлов, XML ≤10 MiB, медиа ≤100 MiB, до 2 000 вопросов. XML ограничен 64 уровнями и 200 000 элементами; DTD и исполняемые инструкции запрещены. Проверяются центральный каталог ZIP, реальные размеры, CRC, симлинки, обход путей и неоднозначные имена после URL-декодирования/Unicode-нормализации. ZIP64, многотомные и вложенные архивы явно отклоняются.

Файлы проверяются потоково; архив не распаковывается по пользовательским путям. XML ограниченно читается в память. Отмена через context останавливает обработку. При интеграции обработка архивов будет отделена от игровых команд.

## Проверено 21.10.2026

- Семантический v4/v5 → экспорт v5 → повторный импорт, включая параметры, комментарии и хеши медиа.
- Более 30 синтетических пограничных случаев: размеры, CRC, отмена, пути, алиасы, XML, неизвестные поля и ошибки экспорта.
- Полный `go test -race ./...`, `go vet ./...`, сборка и отдельный CLI-проход sample → validate → convert → validate.
- Оригинальный и повторно экспортированный демонстрационные XML проходят **официальную SIQ v5 XSD** через `xmllint`.

Ещё не подтверждены: корпус из 100 разрешённых пакетов, доля 95% на репрезентативной выборке и открытие в настольных SIQuester/SIGame. Синтетический корпус и XSD эти проверки не заменяют.
