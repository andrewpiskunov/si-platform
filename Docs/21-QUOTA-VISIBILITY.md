# Видимые квоты перед загрузкой

Продолжение FR18: пользователь видит занятый объём, остаток и ограничения до импорта SIQ, медиа или оформления. Этот этап не вводит тарифы и не меняет существующие квоты. ИИ-бюджет добавляется вместе с ИИ; экспорт и политика хранения — отдельный следующий этап FR19.

## Контракт

GET `/api/usage`, только действующая аккаунтная сессия, no-store. Проверка роли не нужна, API-токены не допускаются: их доступ к бюджетам будет частью отдельного API/MCP. Клиент не передаёт user_id. Ответ:
- storage: used_bytes, limit_bytes=10737418240, remaining_bytes=max(0,limit-used). Используется существующий library.StorageUsage под блокировкой аккаунта; это учётная квота, не обещание физической дедупликации.
- packs: used (неудалённые пакеты), limit=200, remaining.
- themes: used (все сохранённые темы, включая обычное удаление), limit=100, remaining; удаление темы сохраняет версии для уже начатых игр и не освобождает квоту.
- uploads: active (uploading/queued/processing с expires_at>clock_timestamp), limit=2, remaining. Не раскрывать общую загрузку других пользователей.
- limits: pack_revisions=500, theme_revisions=100, siq_bytes=262144000, media_bytes=104857600, theme_bytes=5242880.

Существующие ограничения проверяются сервером в момент записи. Снимок не резервирует место. После обработки размер может увеличиться; итог нельзя точно предсказать по размеру ZIP/оригинала. Нулевой остаток показывается честно, отрицательных значений нет. Истёкшая загрузка не занимает отображаемое активное место, так же как очистка при новом Create. Не менять состояние загрузок из GET.

## UI

Переиспользуемый блок «Лимиты и использование» в аккаунте, мастерской перед SIQ, редакторе перед медиа и библиотеке оформлений перед ZIP. Объём/остаток, число пакетов/тем/активных загрузок, применимые лимиты версий и файлов. В редакторе текущая версия пакета уже доступна, показывать N из500; для выбранной темы N из100. Объяснение: «Учитываются сохранённые версии и подготовленные файлы. Размер после обработки может вырасти. Остаток не резервирует место». Для тем отдельно объяснить сохранение удалённых версий.

Обновление при открытии и после своих create/delete/upload/attach/theme-save, плюс кнопка «Обновить использование». Ошибка показывает «Не удалось обновить использование» и сохраняет предыдущий снимок как неактуальный; не превращается в нулевой остаток и не ломает форму/редактор. Статические лимиты видны даже без ответа. Параллельные компоненты объединяют запрос; запоздавший ответ после выхода/смены аккаунта не отображает прежние данные. Общий долговременный кеш между аккаунтами не нужен; можно предпочесть независимый компонент с явным refresh trigger для простоты.

## Проверка

PG/API: точное совпадение authoritative StorageUsage, версии/readyupload/theme accounting, own-only, deniedanonymous/token/revoked/deleted, limitboundaries/remainingzero, expiredactiveupload exclusion. Web: форматирование/ошибкаunknown/stale snapshot/generation guard, UI до первого POSTupload. Chromium: account/studio/editor/themes, update aftermutation, simulated503preserves formandusage, differentaccountnooldcache, mobile/keyboard. Никаких новых платных сервисов.
