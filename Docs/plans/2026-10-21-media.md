# Подготовка и воспроизведение медиа — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Один независимый обзор всего этапа после интеграции; один проход исправлений с регрессиями.

**Goal:** Автор загружает и проверяет медиа, а комната безопасно и синхронно показывает текущий фрагмент всем допущенным участникам.

**Architecture:** Изолированный FFmpeg-процесс за Go-интерфейсом; существующая durable-очередь ingest готовит SIQ и отдельные файлы. Неизменяемая ревизия хранит исходник и проверенные производные. Движок v2 хранит готовность/сроки, HTTP выдаёт только разрешённый текущий файл.

**Tech Stack:** Go, PostgreSQL/pgx, local/S3, FFmpeg/ffprobe, Linux bubblewrap+prlimit, SvelteKit/TypeScript, Playwright.

**Spec:** [Docs/15-MEDIA.md](../15-MEDIA.md). База — `45b531f`, этап игровых правил проверен и слит в локальный main. Пользователь разрешил полную реализацию без повторных подтверждений.

## Global Constraints

- До 12 игроков и 20 зрителей; медиа не передаётся через WebSocket, снимок ≤60 KiB, очередь ≤64 KiB.
- Вход/каждая производная ≤100 MiB, длительность ≤600 с, изображение ≤16 Мп, видео ≤3840×2160; две обработки, ≤180 с и 512 MiB адресного пространства на процесс. Условия проверяются настоящими инструментами; если конкретная сборка не укладывается, ошибка документируется, лимит не снимается молча.
- Подготовка ≤10 с ожидания игроков за один интервал, общий старт через 750 мс; только серверное время. Ведущий явно ждёт, продолжает либо пропускает.
- Оригинал и структура SIQ сохраняются; невалидный файл диагностируется, не исполняется. Медиа ответа не предзагружается игроку до раскрытия.
- Sandbox обязателен для FFmpeg: сеть/чужая файловая система недоступны, argv без shell, очищенное окружение с фиксированным MALLOC_ARENA_MAX=2, bounded stdout/stderr/output, завершение всей группы при отмене.
- Все записи объектов сначала резервируются под существующим BlobGCLockSQL; очистка учитывает производные. Новые миграции, без изменения применённых.

## Review Focus

1. Ответ или следующий фрагмент угадан по ID/старому билету — повторная проверка разрешённой проекции на каждом GET.
2. Транскодер завис, читает файл/сеть или выдаёт неограниченный поток — реальные sandbox/timeout/output-limit tests.
3. Автор редактировал пакет во время загрузки/отозвал токен — прикрепление с ревизией и повторной авторизацией; локальная правка сохраняется.
4. Игрок спрятал вкладку или вернулся посреди показа — readiness и позиция привязаны к текущему stage/instance, пауза замораживает позицию.
5. Сбой между загрузкой производной и записью ревизии — durable reservations, повтор без дубликатов и без удаления общего хеша.

## Task 1 — Изолированный processor (internal/media/**)

Файлы: `model.go`, `processor.go`, `sandbox_linux.go`, `sandbox_other.go`, `probe.go`, `processor_test.go`, `integration_test.go`. Не меняет библиотеку/ingest/game/UI. Настройка реальных бинарников в пользовательском tools cache разрешена; источники/версии записать в ledger.

**Produces (зафиксировать model.go первым):**
- `Variant{Key string, MIME string, Size int64}`; JSON key/mime/size.
- `Prepared{Kind string, DurationMS int64, Width int, Height int, Standard Variant, Economy Variant}`; JSON kind/duration_ms/width/height/standard/economy.
- `Options{FFmpeg,FFprobe,Sandbox,Prlimit,Directory string}`; `New(Options)(*Processor,error)`.
- `Prepare(ctx context.Context, kind string, source io.Reader, size int64)(*Result,error)`; kind=image/audio/video. `Result{Prepared Prepared, Files []Output}`; `Output{Key,Path,MIME string, Size int64}`; `Result.Close()` удаляет только каталог результата. Processor не пишет blob/БД.
- Ошибки кодированы через `media.Code(err)`: unavailable/invalid/unsupported/too_large/too_long/timeout/canceled. Не возвращать внешнему API команду, путь или stderr.

- [x] RED: размеры/виды/отмена, sandbox argv и ограниченный вывод, некорректные числа ffprobe; watch FAIL.
- [x] Реализовать проверку контейнера и потоков, запрет плейлистов/активного содержимого; ограничить demuxers/protocols и проверить полный decode, не только заголовок.
- [x] Изолировать процесс с read-only runtime, отдельными /input и /output, без сети/секретов; wall timeout, prlimit AS/CPU/FSIZE, threads≤2; закрывать и дожидаться процесса на отмене. Утилиты запускаются по абсолютным путям, без пользовательских argv.
- [x] Создать обычную/экономную производную по Docs15; проверить выходной контейнер/кодек, длительность/размер и SHA256. Нельзя принять частичный файл после таймаута или обрезания.
- [x] GREEN на настоящих синтетических PNG/WAV/MP4/WebP; malformed/oversize/duration/timeout/local-file/network cases. `go test -race ./internal/media`; запуск integration с реальными инструментами обязателен для завершения.

## Task 2 — Хранилище, импорт и прикрепление (root: library/ingest/server authoring)

Файлы: `migrations/00007_media.sql`, `internal/library/{model,validation,service}.go`, новый `media.go/tests`; `internal/ingest/{service,worker,cleanup}.go`, новый `media.go/tests`; `internal/server/media_upload.go/tests`, `authoring.go`, `cmd/server/main.go`, окружение и Dockerfile.

**Consumes:** processor Task1. **Produces:**
- `library.Asset.Prepared *media.Prepared`; исходные Name/Key/Size/MIME продолжают описывать оригинал и SIQ export.
- `ingest.Options.Media *media.Processor`; nil даёт media_pending, не опасный fallback.
- `CreateMedia(ctx,actor,name,size,kind)(Upload,error)`; Upload добавляет purpose/asset (готовый library.Asset). Существующие Create/Append/Complete/Get сохраняются. purpose=siq/media записывается durable; media kind и result_asset добавляются миграцией.
- `library.AttachAsset(ctx,actor,packID,baseRevision,uploadID,asset)(Draft,error)` принимает только доверенный результат ingest; receipt unique(pack_id,upload_id) в той же транзакции, live credentials/scopes и квоты. Повтор возвращает текущий Draft без повторной ревизии. Не перезаписывает документ при конфликте.
- HTTP `POST /media-uploads {name,size,kind}` → Upload; chunk/complete/poll по существующим /uploads/{id}. `POST /drafts/{id}/assets {upload_id,base_revision}` → Draft. Владелец/`drafts:write` обязательны. `GET /drafts/{id}/prepared/{key}?revision=N` выдаёт только подготовленный файл с live ACL; оригинал остаётся attachment.

- [x] RED реальные PG: чужая загрузка, revoked credential, конфликт revision, duplicate attach, квота включает производные, GC не удаляет общий derivative.
- [x] Сохранить job purpose, bounded worker и существующее fencing/cancel-before-retry. Для каждого подготовленного hash расширять durable reservations до Put.
- [x] SIQ использует тот же processor; ошибки медиа прикладываются к точному имени, оригинал/редактируемый черновик сохраняются. Ручная загрузка ready только после полной проверки/Put; результат прикрепляется отдельно.
- [x] Readiness пакета проверяет подготовленность referenced assets и метаданные, в том числе при создании комнаты; пользователь HTTP не может прислать Prepared/Key/issue как доверенные данные.
- [x] GREEN realPG race library/ingest/server; отмена/сбой/повтор, SIQ roundtrip сохраняет оригинальные bytes.

## Task 3 — Медиа в движке и компиляторе (internal/game/**, internal/playpack/**)

Изменить v2_types/command/question/projection/engine, добавить `v2_media.go/tests`; playpack compile и тесты. Контракт согласуется с root до UI, не изменять v1.

**Produces:**
- `game.MediaVariant{Key,MIME string, Size int64}` private; `MediaSpec{ID,Kind string, DurationMS int64, Width,Height int, Standard,Economy MediaVariant}`.
- `TextStep.Media *MediaSpec` (Text сохраняется); проекция `QuestionView.Media *MediaView` только для текущего фрагмента, без Key/имени файла. MediaView: id/kind/duration_ms/width/height, standard/economy `{mime,size}`, start_at_ms, paused_position_ms, playback_end_position_ms и optional stopped_position_ms (включая 0).
- Session private `Content *ContentState` хранит group(question/answer), index, return stage, ready statuses и сроки; SessionView `readiness:[{id,status}]` для текущего этапа (status=loading/ready/error/hidden).
- stages prepare_content/scheduled_content; команды `media_ready {stage_id,instance_id,status}`, `continue_media {stage_id,instance_id}`, `wait_media {stage_id,instance_id}`, `skip_question {stage_id,instance_id,reason}`. media_ready не требует global ExpectedSeq; остальные host+seq.
- `playpack.AssetLookup func(kind,reference string)(game.MediaSpec,error)`; `CompileMedia(doc,qID,lookup)` и `ValidateMedia(doc,lookup)`. Existing Compile/Validate без lookup продолжают диагностировать непроверенные медиа; текстовый профиль совместим. Media ID детерминирован для pinned spec/retries и не содержит имени/хеша исходника.

- [x] RED: prepare→allready→scheduled750ms→present, timeout10s→wait/continue/skip; stale ready, simultaneous12ready, hidden/error, hostonly replic, spectators не блокируют.
- [x] Внедрить проверку metadata и лимитов снимка; не выдавать будущие/answer media до authorised reveal. Specialquestion prelude (получатель/аукцион/ставки) остаётся до подготовки.
- [x] Ready=false на scheduled возвращает ожидание; дубликат status не создаёт новый переход. Pause/recover сохраняют readiness и позицию; resume сдвигает start_at без скачка. Утрата ведущего использует существующую PauseAt.
- [x] Длительность: explicit DurationMS важнее natural duration; waitForFinish сохраняет ручное управление; поздний тик не переписывает запланированное общее время.
