# Полные карточки SIBrowser в публичном каталоге

Статус: согласован пользователем, реализован и проверен. Дополняет согласованный `2026-10-23-sibrowser-sync-design.md`.

## Задача

Пользователь хочет загружать и отображать все данные пакетов, доступные на SIBrowser, включая обложки и ранее пропущенные поля. Изменение охватывает новые и уже импортированные пакеты. Текущий full остановлен по просьбе пользователя: реализация и проверка не возобновляют массовую загрузку SIQ и не устанавливают cron.

## Подходы

1. **Локальная копия метаданных и обложек — предлагаемый подход.** Данные выдаёт наш API, изображения хранятся в нашем object storage. Карточки доступны независимо от SIBrowser; нужны обновление снимков, учёт хранения и повторы.
2. Внешние ссылки на изображения и чтение метаданных при открытии карточки. Меньше хранения, но сайт зависит от доступности источника, посетители обращаются к нему напрямую, труднее ограничить нагрузку. Не соответствует желаемой полной загрузке.

Пользователь подтвердил полный охват полей. Выбор локального хранения, частота обновления и расположение блоков ниже — предложения разработчика.

## Состав данных и отображение

| Данные | Источник и показ |
| --- | --- |
| Название карточки | SIBrowser; основное название в каталоге. Если имя внутри SIQ отличается, показывать его отдельно на странице пакета. Игровой документ не переименовывать. |
| Все авторы | Упорядоченный список имён и ссылок на профили SIBrowser. Исправить текущую потерю всех авторов, кроме последнего. Авторство из SIQ сохраняется отдельно. |
| Обложка | Изображение именно этого пакета на SIBrowser, локальная проверенная копия; если отсутствует, использовать подготовленный логотип SIQ, если он есть. Иначе существующая текстовая обложка. Не выбирать случайную картинку вопроса. |
| Описание публикации | Текст с абзацами и безопасными ссылками. Не исполнять HTML источника. |
| Теги | Все теги SIBrowser; теги SIQ сохраняются. Для списка и фильтра — объединение без дублей. |
| Дата публикации | Дата SIBrowser отдельно от даты пакета SIQ и времени импорта. Не превращать дату без времени в произвольный часовой пояс. |
| Имя и размер исходного SIQ | Имя файла и отображаемый размер источника. Точный размер скачанного архива и объём хранения нашей платформы — разные величины, подписывать раздельно. |
| Число вопросов | Значение SIBrowser и фактическое число из импортированного SIQ. Обычно показывать фактическое; при расхождении показывать оба с источником. |
| Типы вопросов | Текст, изображения, аудио, видео и проценты источника. Проценты могут пересекаться и не обязаны суммироваться в 100%; отдельные полосы, не круговая диаграмма. |
| Категории | Все названия и проценты источника, включая нулевые значения. Не превращать отсутствующее значение в ноль. |
| Скачивания | Подпись «Скачиваний на SIBrowser», время обновления. Не увеличивать собственные счётчики платформы. |
| Исходные публикации | Все ссылки «Оригинальное сообщение» (VK и другие реально разрешённые источники), ссылка на карточку SIBrowser. Не хранить временные подписанные ссылки скачивания. |
| Раунды, темы, предпросмотр вопросов | Структура из SIQ и доступный на SIBrowser текст предпросмотра. Предпросмотр свернут под явной кнопкой «Показать вопросы — спойлеры». Не публиковать ответы, комментарии ведущего, технические файлы и произвольные assets через этот API. Медиа в предпросмотре обозначать типом, как в наблюдаемых карточках SIBrowser. |
| Данные SIQ | Существующие язык, сложность, возрастное ограничение, сведения об авторах/пакете и игровой контент сохраняются. Доступные сведения о пакете показывать на странице; вопросы, ответы и медиа остаются доступны штатному игровому механизму. |
| Происхождение | Внешний ID, ссылка на источник и время последнего успешного обновления карточки. Лицензия остаётся неизвестной, если её не указали; существующая политика скачивания не меняется. |

Каталог: обложка, название, все авторы, теги, дата, число вопросов/раундов и компактная статистика источника. Полная страница: обложка и описание, сведения о файле, категории и состав вопросов, структура пакета, раскрываемый предпросмотр, авторство и источники. Большие тексты и предпросмотр не включать в ответ списка каталога; загружать на странице пакета по необходимости. Использовать текущий стиль и адаптивную сетку сайта. На мобильном блоки идут в одну колонку.

Закладки посетителя SIBrowser, рекомендации «похожие пакеты», реклама и глобальные счётчики сайта не являются данными пакета и не копируются. Ссылки «играть/скачать» заменяются действующими возможностями нашей платформы; ссылка на оригинальную карточку остаётся.

## Парсинг и ограничения

На 2026-10-23 проверены карточки 22419, 25928 и 25924. На странице рядом с главным пакетом есть другие пакеты; нельзя искать первое изображение или все ссылки авторов по всему документу. Например, на странице 25928 найден логотип пакета 22419 в рекомендациях — это не обложка 25928.

Сначала определить главный пакет по маршруту и структурному контейнеру. Извлекать только принадлежащие ему метаданные, не дублировать desktop/mobile-блоки. При непредвиденной структуре не заменять хороший снимок пустыми значениями. Отсутствие необязательного поля в валидной карточке допустимо. HTTP 404, таймаут или повреждённый HTML не означают удаления карточки и обложки у нас.

Сохранить существующие ограничения HTTP: общий интервал запросов, таймауты, публичные IP, проверка каждого редиректа и допустимых доменов, ограничение HTML. Токен API никогда не отправляется источнику. URL обложки должен относиться к ожидаемому пакету и разрешённому origin; внешние ссылки отображаются после проверки схемы, но автоматически не обходятся. Обложки принимаются с ограничением размера и разрешения, проверяются и преобразуются штатным изолированным медиапроцессором. Сохранять только безопасные подготовленные варианты изображения, учитывать их в квоте и удалении неиспользуемых объектов.

## Хранение и API

Метаданные источника — отдельный типизированный снимок, связанный с `(source, external_id)` и импортированным `pack_id`, с версией парсера, временем проверки и последнего успеха. Не включать изменяемые счётчики и описание в зафиксированный SHA/receipt SIQ; обновление карточки не создаёт новую игровую ревизию и не меняет оригинал архива.

Карточка API содержит компактную проекцию источника, полная информация и предпросмотр доступны отдельным ограниченным ответом страницы пакета. Применять текущие правила доступности: удалённый, заблокированный или снятый с публикации пакет не выдаёт метаданные, предпросмотр или обложку публично. Нельзя получить другие медиа пакета под видом обложки. Серверный endpoint записи доступен только действующему служебному владельцу SIBrowser с нужным scope и ролью admin; привязку к import receipt проверяет сервер. Не доверять pack_id/произвольным ссылкам клиента.

Поиск учитывает видимое название, всех авторов, описание, теги и названия тем. Текст вопросов/ответов не включать в общий поиск. Фильтр тегов работает и для тегов источника. Значения SIQ и источника хранить раздельно, не скрывая расхождений. Метаданные источника не стирают правки игрового документа. Удаление/снятие публикации оператором не отменяется обновлением карточки.

Обложки и сохранённые метаданные должны участвовать в действующих механизмах квот, очистки и удаления связанных данных. Не создавать неучтённые файлы вне object storage. Подробности схемы, индексов, контрактов и лимитов делегируются реализации; окончательные лимиты фиксируются в эксплуатации.

## Обновление и заполнение существующего каталога

- Новые пакеты: получить полный снимок карточки и обложку при импорте; ошибка этих необязательных данных не переводит пригодный SIQ в rejected и не останавливает публикацию. Задача догрузки остаётся сохранённой.
- Отдельный режим `--mode=metadata`: обойти уже импортированные записи, заполнить пропущенные данные и обновить устаревшие. Не скачивать SIQ, не создавать пакеты, не менять checkpoint bootstrap и статусы публикации. Предусмотреть ограничение количества и принудительное обновление снимка для оператора.
- Обычный incremental обновляет данные встретившихся карточек не чаще раза в сутки; сначала повторяет ранее неуспешные задачи метаданных с backoff. Все старые карточки обновляются отдельным metadata-проходом, а не только первой страницей выдачи.
- У метаданных и обложек отдельные статусы/ошибки/сроки повтора. При ошибке изображения хороший текстовый снимок может обновиться, старая рабочая обложка остаётся. Подтверждённое отсутствие обложки переводит отображение на логотип SIQ или заглушку.
- Один общий advisory lock с full/incremental; потеря lease отменяет запросы и защищает записи поколением запуска. Повтор после отмены или неопределённого ответа идемпотентен. Метаданные не переписывают состояние импортирования SIQ.
- JSON-отчёт отдельно считает карточки/обложки, пропуски и ошибки. Полный импорт в текущем окружении не запускать; после реализации допустим ограниченный backfill только уже импортированных записей с проверкой результата, поскольку пользователь просит дополнить их данные.

## Критерии готовности

1. Fixtures страниц с обложкой и без неё, несколькими авторами, тегами, описанием, источниками, нулевыми процентами, desktop/mobile-дублями и рекомендациями; корректное извлечение только главного пакета.
2. Ограничение размера/разрешения изображения, неверные форматы, редиректы, HTTP ошибки и отсутствие утечки API-токена; медиа обрабатывается в sandbox.
3. PostgreSQL/API: повторное обновление без дубликатов, квоты/очистка, отзыв прав, блокировка/withdraw/delete, отдельные повторы карточки и обложки, потеря lease, неизменность SIQ и bootstrap checkpoint.
4. UI: обложка и fallback, все поля, пустые значения, несовпадения данных, работа поиска/тегов, доступный раскрываемый предпросмотр без ответов и комментариев ведущего, мобильное отображение и длинные русские тексты.
5. Go tests с реальной тестовой БД, frontend check/build и проверки UI; ограниченная догрузка существующего каталога после обновления API. Full остаётся остановленным.
