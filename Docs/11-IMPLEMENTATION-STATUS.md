## Решения для автономной разработки

- Go и существующий стек сохраняются. Модули пакетов, аккаунтов, игры, каталога и задач имеют отдельные границы; общая PostgreSQL.
- SvelteKit + TypeScript выбран для реализации на основании сравнения в Docs/07. Каталог получает SSR; Go остаётся владельцем всех бизнес-правил. Размер игровой сборки измеряется после появления интерфейса, выбор не объявляется доказательством скорости.
- Локальная разработка продолжает существующий репозиторий. Сервисы упаковываются для самостоятельного размещения; выбор коммерческого аккаунта, домена и региона не подменяется случайным размещением.
- Хранилище имеет локальный и S3-совместимый адаптеры. Интерфейс использует непрозрачные ID файлов и авторизованную выдачу, а не публичные адреса приватных ответов. Облачный endpoint настраивается окружением.
- ИИ работает через настраиваемый серверный провайдер; тестовый провайдер явно обозначается и не выдаётся за реальную генерацию. Без ключа функция объясняет отсутствие настройки; остальной продукт работает.
- Каждая подсистема получает короткую спецификацию/план, тесты и проверку интеграции. Законченные этапы сохраняются в локальный main. Пользователь уже разрешил реализацию; рутинные решения не требуют повторного подтверждения.

## Что потребует внешних условий

Публичный домен/облако, реальные ключи ИИ, права/доступ к стороннему каталогу, репрезентативные чужие пакеты и участие людей в пилоте нельзя заменить синтетическими результатами. Для них будут готовы адаптеры и процедуры, а в итоговом отчёте останется фактический статус. 99,9% доступности за месяц подтверждается только историей работающего сервиса; измерения на локальной машине не выдаются за испытания целевого стенда.
