# Мои комнаты и возвращение ведущего — 23 октября 2026

В кабинете `/account#my-rooms` появился список созданных аккаунтом комнат. Он включает приватные и публичные игры, завершённые игры в пределах срока хранения; показывает пакет, фазу, количество игроков/зрителей, дату создания, отметку создателя и текущую роль. Из раздела «Комнаты» есть ссылка «Мои комнаты».

Кнопка «Продолжить ведение» возвращает на исходное место ведущего. После передачи роли кнопка меняется на «Вернуться в комнату», а права остаются правами игрока/зрителя. Удалённое место не восстанавливается. Для завершённых игр открываются результаты. Приглашением и настройками ведущий управляет внутри комнаты.

## Хранение и API

- `GET /api/my-rooms?offset=0`: 50 комнат на страницу, новые первыми, `next_offset` для продолжения. Ответ содержит только краткие метаданные. Истёкшие комнаты исключены.
- `POST /api/my-rooms/{room}/session` с `{}`: новая сессия исходного участника. Аккаунт, его действующая сессия, владелец комнаты, срок жизни и активное место проверяются на сервере. API-токены не допускаются.
- Связь аккаунта уже есть в `room_packs.owner_id`, исходное место берётся из неизменяемого события `room_created` (seq=1). Миграция не нужна, ранее созданные комнаты работают.
- Восстановление не меняет роль, участников, приглашение, счёт или правила. Оно меняет токен места, переносит управление в новую вкладку и закрывает прежние WebSocket-подключения этого участника. Повторная проверка токена при подключении закрывает гонку с авторизацией старого соединения.
- Пригласительная ссылка не восстанавливается из хеша. Ведущий может создать новую в комнате; открытие кабинета не отключает действующие приглашения.
- Применяются существующие сроки хранения комнат. Это не бессрочный архив.

## Проверки

`internal/server/my_rooms_test.go`: свой/чужой аккаунт, приватность, исходное место, ротация токена, устаревшее подключение, передача ведущего, удалённый участник, завершённые/истёкшие комнаты, API-токен и отозванная сессия.

`e2e/my-rooms.mjs`: создание приватной комнаты, вход в новом браузерном контексте без sessionStorage, восстановление ведущего, создание приглашения, перенос в другую вкладку и мобильная ширина. Временный аккаунт удаляется после проверки.

Локальный API работает в контейнере `si-platform-sibrowser-api` на 8081. Для проверки обновлён `/app/server` внутри этого контейнера; при пересоздании контейнера нужно собрать образ из актуального исходного кода.
