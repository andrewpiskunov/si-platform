Проект единой веб-платформы для проведения «Своей игры» с темами оформления, создания пакетов, работы с ИИ и публикации в каталоге.

В репозитории — Go API, PostgreSQL, браузерный интерфейс SvelteKit, комнаты до 12 игроков, редактор и каталог пакетов SIQ. Новое игровое ядро поддерживает спецвопросы, финал, ставки, таймеры, восстановление и синхронный показ подготовленных изображений, аудио и видео. Добавлена библиотека своих тем ZIP с проверкой палитры и изображений, предпросмотром и закреплением версии за комнатой. Добавлен встроенный ИИ-помощник с оценкой бюджета и проверкой предложений автором; реальный провайдер включается отдельной настройкой ([инструкция](Docs/24-AI-AUTHORING.md)). MCP-инструменты подключаются ограниченным токеном ([инструкция](Docs/25-MCP-AUTHORING.md)). Полный MVP ещё в разработке: разрешённый импорт каталога и эксплуатационные испытания перечислены в [статусе](Docs/11-IMPLEMENTATION-STATUS.md).

**Запуск:** [браузерная игра и мастерская](Docs/13-WEB-AND-AUTHORING.md). Для локального запуска нужны Go, PostgreSQL и Node; для обработки медиа — Linux/WSL и FFmpeg с sandbox (см. инструкцию); веб открывается на **http://localhost:5173**. `go run ./cmd/demo` проверяет 12 одновременных участников через настоящий HTTP/WS API.

Docker Compose подготовлен для самостоятельного размещения; его запуск в этой среде пока не проверен.

### Регистрация по почте

Новая форма `/login?mode=register`: почта, имя на любом языке (до 64 символов), пароль и повтор. Аккаунт создаётся после подтверждения адреса; ссылка действует 24 часа. Вход принимает почту или старый логин. «Забыли пароль?» отправляет одноразовую ссылку на 30 минут; после смены пароля прежние сессии и API-токены отзываются. У старых аккаунтов без привязанной почты восстановление по почте недоступно. Старый API регистрации по `username` сохранён для совместимости инструментов и тестов.

`./scripts/dev-local.sh` по умолчанию сохраняет письма в `.local/mail/*.eml` (папка 0700, файлы 0600). Откройте файл и скопируйте полную ссылку в браузер. Никакие письма при этом не уходят наружу. Файловая доставка разрешена только при loopback `ALLOWED_ORIGIN`; файлы содержат одноразовые ссылки, не публикуйте их. После локальной проверки их можно удалить.

Для настоящей отправки задайте `SMTP_ADDR` (host:port, STARTTLS), `SMTP_FROM`, при необходимости `SMTP_USERNAME` и `SMTP_PASSWORD`, а также публичный `ALLOWED_ORIGIN`. Уберите `MAIL_DIRECTORY`, если включаете SMTP. Без настройки транспорта email-регистрация и восстановление возвращают недоступность; вход в существующие аккаунты остаётся доступным. Реальная SMTP-доставка требует настройки вашего сервера и не проверялась локальным тестом.

Проверка email-сценария при запущенном локальном проекте:
`BASE_URL=http://localhost:5175 node e2e/email-accounts.mjs` (при необходимости задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` и `MAIL_DIRECTORY`). Тест работает только с локальными письмами, проверяет имя на кириллице, японском и арабском, подтверждение, сброс и повторный вход.
